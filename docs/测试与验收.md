# 测试与验收

## 默认回归

`python -m scripts.check_release` 使用临时 SQLite、固定行情、假模型及受控 HTTP 响应，禁止 TCP 连接，不需要密钥，也不读取本机 `.env`。覆盖交易状态、记账幂等、历史更正、循环完成检查、工具发现、RAG 排序与引用核验、任务恢复、授权、用量账本和健康检查。

`node --test tests/frontend/*.test.cjs` 验证 Web 页面状态与数据展示逻辑。小程序目录运行 `pnpm test`、`pnpm build`。浏览器 DOM 测试通过不等于所有设备视觉验收通过；微信真机仍需自己的 AppID 和可访问服务地址。

## 固定季报

运行 `python -m scripts.prepare_report_fixtures` 从来源清单下载 PDF，检查 SHA-256，生成不纳入 Git 的 `documents.json` 和原文件。再运行：

```bash
python -m unittest tests.test_fund_report_query tests.test_fund_report_evals
```

它验证固定样本的检索与评分逻辑，不代表在线大模型的答对率。真实模型评测由 `scripts/eval_agent_loop_live.py`、`scripts/eval_fund_report_mode.py` 等独立入口执行，先阅读各脚本 `--help` 和对应文档，确认费用与存储位置。

## 外部服务与故障恢复

这些测试不在默认回归中运行，必须使用独立服务，不能指向自己的真实账本：

- `tests/test_ai_governance.py` 的 Redis 测试需要 `TEST_AI_REDIS_URL`。
- `tests/test_reliable_jobs_postgres.py`、`tests/test_reliable_job_celery.py` 分别覆盖数据库竞争和实际队列执行，按文件中的显式环境开关运行。
- `tests/test_task_authorization_openfga.py` 检查实际授权模型，需独立 OpenFGA 配置。
- `tests/test_reliable_job_process.py` 会终止自己启动的测试 Worker，检查执行接管与阶段恢复。
- `tests/test_backup_restore.py` 的 Docker 恢复演练需 `RUN_RECOVERY_DOCKER_TEST=1`，会创建隔离容器和卷。流程见 [备份恢复与账务核对](备份恢复与账务核对.md)。

默认 CI 仅执行确定性回归和前端构建。服务级测试、云端部署和在线模型质量需分别记录环境、输入、时间与结果；不能由单元测试通过推导为生产验收通过。
