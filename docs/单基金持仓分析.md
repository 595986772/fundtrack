# 单基金持仓分析

更新日期：2026-09-08

## 使用入口

研究终端 → 持仓分析。左侧选择基金后仍停留本页；手机从“功能”选择“持仓分析”，从导航选择基金。

- 披露概览：已披露股票/债券小计、证券覆盖、行业分布、重仓证券和来源。
- 持仓变化：按股票、债券、行业分别比较同来源的上次已保存非空披露。
- 重新读取：仅查询本地已保存数据。外部同步仍使用原有手动同步入口。
- 交给 AI 解读：转到现有助手并填好带基金代码和披露日期的问题，用户发送后才调用模型。

## 数据口径

百分比均占单只基金净值，不再乘以组合中的基金权重。股票/债券证券明细与行业配置不能相加。
同报告期证券小计用于计算披露覆盖；不同日期不合并总覆盖。超过 100% 时保留原始比例并说明潜在杠杆/口径问题。
“未解释净值比例”只是已披露证券覆盖以外的部分，不是现金比例。

当前数据源没有完整现金配置，也没有可靠的“联接基金持有目标 ETF 比例 × 目标 ETF 底层持仓”映射。
缺失项明确标注，不以基金名称或跟踪指数替代实际持仓；ETF 联接基金会在数字前显示能力边界。

变化单位为百分点。只有两次均披露的项目才计算差值；新出现、未再披露不能等同于买入或清仓。
历史读取不自动下载补齐，也不混合冻结 fixture 和数据库数据。只有一份报告时显示“暂无可比记录”。

## 代码组织

- `app/services/fund_disclosures.py`：延续原有采集与落库；新增只读历史报告查询，不改组合查询接口。
- `app/services/fund_holdings.py`：单基金事实、集中度、覆盖与历史比较，不调用模型。
- `app/routers/funds.py`：新增 `GET /api/v1/funds/{fund_code}/holdings-analysis`。
- `app/services/fund_agent_tools.py`：`get_fund_holdings_tool` 复用相同分析，截断长名单时记录省略数。
- Agent 路由、能力白名单、执行器：分别负责选对单基金工具、授予只读权限、绑定当前基金代码。
- `app/static/fund-holdings.js` / `.css`：独立页面与请求状态，序号隔离快速切换基金的慢响应。
- `workspace-pages.js`：声明单基金路由 `#overview/holdings`；原 `#portfolio/exposure` 回到组合风险页。

组合的穿透前端入口、加载状态和渲染函数已移除；后端 `PortfolioExposureService`、REST 和 Agent 工具继续保留，供组合风险与事件分析使用。
