# FundScope 小程序本地开发版

本目录是独立的原生微信小程序，不是把原网页套进 web-view。TypeScript 编译为 JS，WXML/WXSS 负责原生页面；所有资产数据复用 FastAPI 与现有数据库。原来的网页入口不变。

## 先看效果

后端运行时打开 <http://127.0.0.1:8000/mini>。

这个地址是**浏览器预览，不是微信模拟器**。它读取同一份编译后的 Page 逻辑和 WXML，网络请求指向真实 FastAPI。保存持仓、记录交易也会真正写入当前用户的数据库，不是无副作用的演示页面。

首次默认连接 `http://127.0.0.1:8000`。先在 Web 注册账号，再在设置页登录；`chen` 只是匿名开发模式的示例 ID，不是预置账号。已有组合若只有权重，金额显示 `--`，点“补录实际持仓”填写份额、剩余成本、基准日即可。不会自动假设用户有多少钱，也不替用户下单。

底部与网页版业务导航对齐为 **资产、事件情报、社区热点、板块雷达、AI投研**。复杂功能进入独立详情页，不在首页堆叠。详细入口和操作验收见 [功能对应与测试](FEATURE_PARITY.md)。

这里对齐的是面向用户的金融业务，不迁移开发者模式、MCP/Worktree 管理、测评管理台。微信一键登录、云部署和正式发布不在本轮范围内。多视角按钮只准备问题，发送后复用已有 Agent 与工具权限，不保证每一问都会调多个子 Agent，也未另行部署 TradingAgents。

净值更新按钮只提交现有后台同步任务，提交成功不等于行情已更新。任务完成后点资产页刷新，日期以数据源实际披露为准。页面切换只读取快照，不触发新闻采集。

## 添加其他基金

在“资产 → 基金库”输入基金名称或六位代码，点击搜索图标，再对目标基金点击“导入”。搜索复用后端公募目录，每次最多展示 12 项；这不是总共只能导入 12 只，完整代码可以缩小匹配范围。覆盖以 AKShare/东方财富公开目录为准，不保证所有私募、境外或下架产品均可接入。

导入是后台任务，会补齐档案和历史净值；只有任务完成且基金进入可用列表，页面才显示成功。页面内自动查询已提交任务的进度，切走后暂停查询，回来可以恢复；查询失败时点击“检查导入进度”，不会重新建任务。提交响应丢失时重试沿用幂等键。

成功后进入持仓录入或交易记账，基金下拉列表便会包含新基金。导入不会自动新增持仓、分配金额或执行交易。每个账本现有的最多 10 只基金限制不变。市场搜索和导入均需手机已连接后端，不能解决微信本地网络权限问题。

交易记账的“买入”显示全部已导入基金，“卖出”只显示该组合当前正份额持仓。买入页也可点击“从基金库选择／导入”，选中已导入基金后返回原组合记账；尚未导入的需等待导入完成再选择。每次返回交易页都会重读列表，并按基金代码恢复选择。切换到另一只基金时清空原成交份额与价格，避免误记；未选择新基金直接返回则保留原草稿。

## 构建与测试

需要 Node.js 20+。终端进入本目录后：

```bash
pnpm install --frozen-lockfile
pnpm build
pnpm test
```

使用 pnpm 11.19.0，配置中明确不运行 sharp 的安装脚本，使用其预编译平台包。依赖锁定在 `pnpm-lock.yaml`。

后端核心回归在项目根目录、激活 Python 虚拟环境后执行：

```bash
python -m scripts.check_release
```

测试使用临时数据库，不修改用户实际持仓。编辑 `src/` 后重新构建；不要修改生成的 `dist/`。

## 微信开发者工具

1. 在微信开发者工具中导入本目录 `miniprogram/`，不要选择 `src/`。
2. `project.config.json` 将小程序根目录指定为 `dist/`，发布版使用游客 AppID。真机测试时填入自己的 AppID，并用有开发权限的微信账号登录开发者工具。
3. 编译使用微信基础库 **2.20.2 以上**（建议开发者工具最新稳定基础库）；聊天需要 `wx.request.onChunkReceived` 接收 SSE，图表使用 ECharts for Weixin 的 Canvas 2D 适配器。
4. 本机模拟器连接 `http://127.0.0.1:8000`，后端要先启动。
5. 本地项目配置 `urlCheck: false` 仅服务于开发，不代表发布时可跳过合法域名要求。

本轮已做 TypeScript 编译、业务测试与浏览器手机视口检查；**尚未在微信开发者工具或手机微信上完成真机验收**。

如果手机还是旧版三个入口：先执行 `pnpm build`，再在微信开发者工具点“编译”，重新“预览”扫码。刷新旧二维码的页面并不等同于加载最新小程序包。更新小程序不会修改你已保存的账本。

## 手机连接本机

`127.0.0.1` 对手机而言是手机自己，不是 Mac。开发联调时手机和 Mac 连接同一局域网，后端监听 `0.0.0.0`，小程序“我的”中填写 Mac 的局域网 IP 和端口。防火墙需允许对应连接；仅在可信局域网使用本地匿名模式。

现有服务使用 8000 端口时，不要再重复启动另一个 8000 服务。修改监听地址需要停止原服务后再启动：

```bash
python -m uvicorn main:app --host 0.0.0.0 --port 8000 --reload
```

是否支持当前调试方式，以微信开发者工具的真机调试能力为准。正式小程序需要真实 AppID、部署后的 HTTPS 后端、合法请求域名和认证配置；本轮没有替你购买、部署或对公网开放服务。

## 登录与安全边界

- 网页继续使用 HttpOnly Cookie，小程序通过 `POST /api/v1/auth/token` 获取同一套可撤销 Session 的 Bearer token，没有另建一份用户数据库。
- `/auth/me` 和 `/auth/logout` 同时支持两端；显式 Bearer 优先。无效的 Bearer 不会退回网页 Cookie 或本地匿名用户。
- token 只存客户端会话存储，后端仍保存哈希。密码不持久化，模型 API Key 始终留在后端。
- 本地 `AUTH_REQUIRED=false` 时支持旧用户 ID，方便继续访问已有学习账本；**不适合公网部署**。正式服务必须启用认证及 HTTPS，不能靠前端填写 `user_id` 隔离用户。
- 第一版未新增微信注册流程；可用网页版已经注册的 FundScope 账号登录。微信 OAuth 以后使用 `wx.login → code → 后端换 openid → FundScope 用户绑定` 单独实现。
- 浏览器预览有独立存储空间，不读取或覆盖原网页的未保存表单和登录令牌。

## 源码导航

交易记账新增「收益时间」估算：按北京时间 15:00 和交易日历判断适用净值日、预计确认日及首个/最后收益净值日。只预览不会创建持仓，实际记账仍按成交回单；旧流水不补造下单时间。完整规则和测试见 [基金交易与收益时间](../docs/基金交易与收益时间.md)。

```text
miniprogram/
  src/lib/api.ts             网络、Session、账号隔离
  src/lib/format.ts          金额格式、自然日窗口、图表选项
  src/lib/ledger.ts          表单校验、交易幂等键
  src/lib/trade-timing.ts    显式北京时间输入，后端收益日期估算契约
  src/lib/jobs.ts            持久化任务编号、恢复轮询、幂等提交
  src/lib/stream.ts          原生分块接收、UTF-8/SSE 解码、取消与错误
  src/lib/navigation.ts      详情导航、按账号隔离的投研草稿
  src/lib/reports.ts         业务字段中文格式化，不重算金融结论
  src/pages/                十一个原生页面，每页 TS + WXML + JSON
  src/components/ec-canvas/ 上游图表组件（保留许可）
  src/app.wxss              原生共享样式
  scripts/build.mjs          编译后资源与 Lucide 图标生成
  preview/                  仅本地浏览器适配层
  tests/                    无网络的业务模块测试
```

数据流：小程序页面 → Bearer/本地身份 → FastAPI Router → 现有业务服务 / Agent / Worker → SQL 数据库 → 结构化响应或 SSE → 页面渲染。盈亏和求解算法不在小程序重复实现。

后端补充了决策复盘的 POST 兼容路由、采集/研究任务的可选幂等编号，以及只读交易时间估算和流水时间快照；原 PATCH 接口与网页请求保持兼容。浏览器预览适配层不打入原生小程序。
