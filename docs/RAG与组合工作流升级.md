# RAG 与组合工作流升级

## 目标与范围

让季报检索、组合分析和有限补查成为一条可实际使用、可解释、可恢复的链路。
复用现有 FastAPI、LangGraph、Chroma、SQL 快照、调用治理和授权，不再搭建另一套 Agent。
保留标准分析、多角色分析、单基金季报问答及旧报告的读取能力。

## 共同约束

- 基金代码、组合所有权和文档版本由后端校验，模型不能扩大任务权限。
- 不修改原始 PDF 和已有 evidence_id；新检索算法使用独立版本标识。
- 表格数字仍由结构化解析核验，不交给精排模型计算，也不把未找到当成零。
- 每期独立保留证据；相似度、精排分数不是事实正确性或投资置信度。
- 精排超时可明确回退到融合排序；额度拒绝、取消、授权失效不得吞掉。
- 精排等新增模型请求也要预留和结算；没有供应商 usage 时标记待确认。
- 已冻结报告恢复时不访问最新数据；补查先完成再冻结，后续补查生成新版本。
- 公开数据下载仍需用户明确授权；只读本地资料不等于授权自动联网刷新。
- 不强制开启小红书采集，不执行交易，不扩展到未批准的第三方来源。
- 新增关键代码附中文说明；假数据测试与真实供应商验证分别记录，不混称线上验证。

## 实现组织

检索算法与供应商适配从 `fund_reports.py` 中分离，后者继续负责基金/文档作用域及证据装配。
分析计划是可序列化的数据，不保存客户端、Python 函数或任意可执行模型指令。
组合证据采集依赖计划；图节点消费冻结分区。单基金与组合共用季报检索能力。
补查控制器记录缺口、动作、消耗和结果，避免模型在不同工具之间绕过统一次数上限。

- 浏览器使用真实 Web 页面和真实图生成的固定报告，拦截写请求；检查问题/条件提交、证据展开、失败/旧报告、桌面与移动 Web 布局。小程序本轮未新增表单，旧请求仍走默认综合模式。

### 验收时修正的边界

- 同一个幂等键换问题、区间或联网授权会被拒绝，不能返回一份被误认为新结果的旧报告。
- 模型失败时，四节点路径不再引用未读取的市场指标，也不把“未查历史”写成“没有历史”。
- 报告进入工具摘要和上下文压缩后，仍保留原问题、原文、页码、季度、版本哈希与缺口。
- 章节补查更换摘录时，不能丢掉已经覆盖的季度或经理章节；失败不破坏旧证据。
- 补查次数先写进 Job 再访问来源，恢复不会重新获得两次预算；冻结之后不补查最新数据。

## 页面怎么用

1. 打开 Web 的 **AI 投研 -> 研究报告**，选择组合和历史区间。有旧报告时展开“历史报告与后续研究”。
2. 填研究问题，选择模式。默认仍为综合分析；选“自动”才按受控关键词规则决定路径，不是声称模型已理解任意意图。
3. 需要适当性讨论时填写持有期限、可接受亏损、近期用款需求。未填的条件会列为追问，不由模型猜测。
4. 默认不刷新公开源。确需填补缺失季报/事件时，勾选“本轮允许补查公开季报与事件”，确认后启动。
5. 完成后核对报告中的原问题与模式。展开“季报证据与补查记录”，查看原文、页码、动作结果和仍未解决的缺口。
6. “继续追问”沿用这份报告的证据；需要新数据时新建研究，不能通过重试旧任务偷换时点。

| 模式 | 实际读取 | 图节点数 |
| --- | --- | --- |
| 配置解释 `explain` | 账务/风险/业绩基线，不额外读取季报、市场、历史决策 | 4 |
| 季报策略比较 `strategy` | 上述基线 + 已保存的两期季报 | 4 |
| 综合分析 `standard` | 基线 + 市场 + 历史决策 + 季报证据 | 8 |
| 多角色研判 `committee` | 与综合模式共享输入，增加机会/风险分析、相互回应、综合 | 13 |

组合季报最多覆盖三只持仓基金，默认按仓位排序；问题明确含基金代码/完整简称时优先限定对象。
每只基金选两个不同季度，每季度最多两个不超过1200字的完整摘录。未覆盖基金和章节不足会显示，不能声称读完全部文档。
普通路径最多两轮解释；多角色五个业务模型阶段。Embedding、精排及供应商层请求不计入这个阶段数，用量仍由现有治理账本记录。

## 数据和模块

```text
网页 / 聊天工具提出问题
  -> API 校验用户、组合、模式、刷新授权
  -> Job 保存 research_plan + 幂等身份
  -> Worker 按计划采集基线与可选来源
  -> 季报：中文 BM25 + 已就绪向量 -> RRF -> 可选精排 -> 分季度保留
  -> 区分证据缺口 -> 最多两次补查 -> 再检查覆盖
  -> 冻结输入、文档版本、原文和补查记录
  -> LangGraph 按模式消费同一快照 -> 模型解释/多角色分析 -> 引用校验
  -> 保存报告 -> SSE 进度 / 网页原文入口 / 基于旧报告追问
```

| 文件 | 本轮职责 |
| --- | --- |
| `app/services/fund_report_retrieval.py` | 中文 BM25、RRF、精排适配、检索截止时间、排序诊断 |
| `app/services/portfolio_report_evidence.py` | 锁定基金及两期版本、按季度整理原文、标记覆盖范围 |
| `app/services/portfolio_research_plan.py` | 规则选路径、用户条件、缺失条件追问、费用与来源边界 |
| `app/services/portfolio_research_repair.py` | 冻结前缺口分类、预算、授权与补查结果合并 |
| `app/services/research_event_fetch.py` | 固定 AKShare 公开来源的限时子进程读取，不写事件库、不调用模型 |
| `app/services/portfolio_research_graph.py` | 按需采集、四/八/十三节点、冻结与恢复 |
| `app/services/portfolio_research_interpretation.py` | 同一证据目录、历史/当前边界、引用解析、明确回退 |
| `app/services/background_jobs.py` / `job_runtime.py` | 请求持久化、幂等比较、执行资格、补查预算落库 |
| `app/static/research-committee.js` / `portfolio-diagnosis.js` | 问题与授权表单、模式、证据和补查记录 |

## 精排配置

`rank-bm25`、`jieba` 已加入 `requirements.txt`，当前 Conda `dl` 已安装。
默认空的 `FUND_REPORT_RERANK_URL` 不发送精排请求，诊断为 `not_configured`；有向量索引时使用 BM25 + 向量 RRF，无索引时使用 BM25。

在 `.env` 填百炼控制台提供的实际工作空间精排 URL，复用 `DASHSCOPE_API_KEY`：

```dotenv
FUND_REPORT_RERANK_URL=https://YOUR_WORKSPACE.cn-beijing.maas.aliyuncs.com/compatible-api/v1/reranks
FUND_REPORT_RERANK_MODEL=qwen3-rerank
FUND_REPORT_RERANK_TIMEOUT_SECONDS=8
```

以上 URL 是占位示例，不能原样使用。配置后重启 API 与 Worker。供应商协议参考[百炼文本排序文档](https://help.aliyun.com/zh/model-studio/text-rerank-api)。
本机尚未配置真实精排地址，因此未做该接口的真实付费联调，不宣称精排已经启用。
纯资产主项数字题直接走已核对表格，不为取数字再调用 embedding/精排。

## 补查的明确边界

- 最多两次动作，共享四十秒检查预算。超时来源不在后台无限运行；固定公开事件读取使用可终止子进程。
- 缺原文章节先查同一对文档；缺季度且获授权才同步公开 PDF（本轮不顺便为整份 PDF 建向量索引）。
- 缺公开事件且获授权才访问已有白名单来源。新事件只冻结进这次报告，不等于刷新全站事件数据库。
- 缺个人条件只列追问，不以此为联网理由；不是无限循环直到“得到想要的结论”。
- 报告恢复使用原快照；崩溃发生在首次冻结之前时可以重新采集，但已经用掉的补查预算不重置。
- 外部模型/来源失败可以降级；额度拒绝、权限撤销、取消必须停止，不伪装成正常完成。
- 引用校验说明证据来自允许的原文，不保证解释一定成立；历史披露和量化风险不能预测未来收益。
