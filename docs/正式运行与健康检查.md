# 单机正式运行与健康检查

这一版使用独立的 `docker-compose.prod.yml`。公开入口只有 Nginx 的 HTTP/HTTPS，API、
PostgreSQL、Redis 和 OpenFGA 没有宿主机端口映射。API 与 Celery Worker 使用同一个
带版本号的镜像，数据库迁移和 OpenFGA 模型初始化完成后才启动业务进程。

## 准备

1. 在仓库外准备一份环境文件，参照 `.env.production.example` 填入不同的数据库密码、
   OpenFGA 令牌和模型密钥。不要使用示例占位值；数据库密码使用 URL-safe 字符。
2. 将公开域名的可信 TLS 证书分别放到 `infra/tls/fullchain.pem` 和
   `infra/tls/privkey.pem`，或通过 `TLS_CERT_DIR` 指向仓库外的证书目录。仓库内证书目录
   被 Git 和 Docker 构建排除；证书私钥不会进入应用镜像。
3. 将 `PUBLIC_HOST` 设为证书匹配的域名，将 `PUBLIC_ORIGIN` 设为完整 HTTPS 来源，
   例如 `https://fund.example.com`。非 443 端口需写进 `PUBLIC_ORIGIN`。
4. 新部署的数据卷是空的，不会自动导入本机 SQLite、PDF 或 Chroma。已有业务数据需要
   单独设计一次性迁移并核对总数；不要把本机数据库文件直接盖到 PostgreSQL 卷上。

本机也能验证容器链路。用 `localhost`、8080/8443 端口和本机自签证书时，浏览器需要
信任这张证书；手机或其他设备不会自动信任它。对外访问需使用域名和可信证书。
本机临时验证可先创建证书（只在自己信任的测试环境使用）：

```bash
mkdir -p infra/tls
openssl req -x509 -newkey rsa:2048 -nodes -days 1 -subj /CN=localhost \
  -addext subjectAltName=DNS:localhost,IP:127.0.0.1 \
  -keyout infra/tls/privkey.pem -out infra/tls/fullchain.pem
```

## 启动

以下命令中的环境文件路径改为自己的私有文件；不要把密钥写在命令行参数里：

```bash
docker compose --env-file /path/to/private/fundscope.env -f docker-compose.prod.yml config --quiet
docker compose --env-file /path/to/private/fundscope.env -f docker-compose.prod.yml build migrate
docker compose --env-file /path/to/private/fundscope.env -f docker-compose.prod.yml up -d --wait
```

`migrate` 只执行 Alembic 升级，`openfga-init` 只建立/校验固定授权模型。API 和 Worker
随后启动。当前只运行一个 API 进程，因为定时简报调度和聊天取消句柄仍在进程内。
容器重建会保留 `postgres_data`、`openfga_postgres_data`、`redis_data` 和 `app_data`。
这些卷不是备份，正式保存用户数据时还需要单独的数据库备份和恢复演练。
此镜像默认关闭需要本机 Chrome 登录态的小红书采集；该能力仍可在本地手动运行。

## 验收

- `GET /health` 维持前端已有状态接口；`GET /livez` 只检查 API 进程。
- `GET /readyz` 从容器内部检查业务数据库、Celery/治理 Redis、OpenFGA 固定模型和
  至少一个响应的 Worker；故障返回 503。公网 Nginx 不开放这两个运维路径。
- 管理员登录后访问 `/api/v1/ops/runtime`，查看排队任务、最久等待秒数和响应的
  Worker 数；普通用户无法读取。队列积压不会让 API 被误判为进程死亡。
- 未登录访问 `/api/v1/portfolios` 应返回 401；不同账号只能读自己的组合。
- Nginx 为聊天及 `/background-jobs/{job_id}/events` 关闭响应缓冲。断线后重新读取
  后台任务状态和同一个 Job 的 SSE，不再次创建任务。普通聊天流断线会结束当前
  进程任务，当前版本不保证逐字续传。
- 将 Redis 或数据库暂时停止后，内部 `/readyz` 应返回 503；恢复后返回 200。
  验收时选择隔离测试环境，避免影响正在使用的服务。

本机自签证书的命令行检查可显式将该证书作为可信根：

```bash
curl --cacert infra/tls/fullchain.pem https://localhost:8443/health
docker compose --env-file /path/to/private/fundscope.env -f docker-compose.prod.yml exec api python -c "import urllib.request; print(urllib.request.urlopen('http://127.0.0.1:8000/readyz').status)"
```

`PUBLIC_ORIGIN`、Secure Cookie 和同源写请求检查共同约束浏览器登录态。小程序使用
Bearer Token，不依赖 Cookie 的 CSRF 机制。API 没有发布宿主机端口；Nginx 在容器网络
内转发请求并设置代理头。SSE 代理空闲等待是两段数据之间的时间，不是整次分析的总时长。

## 本轮实测

2026-09-23 使用独立的 Compose 项目、临时证书和测试密钥启动整套容器；迁移、OpenFGA
初始化、Worker、API 和 Nginx 均通过检查。公网 `/health` 返回 200，未登录组合接口
返回 401，未登录运维接口返回 401，Cookie 跨来源写请求返回 403。演示 Job 的 SSE
逐次收到运行步骤和完成事件，重复提交幂等键复用原 Job。单独停止测试 Redis 后，
内部 `/readyz` 返回 503；恢复 Redis 后返回 200。测试容器和临时卷随后已清理。
这次没有调用真实模型，也没有测试公网域名和受信任证书。
