# 交易日自动简报

## 怎么用

Web 打开 **AI 投研 → 每日简报**（`/#research/briefings`），选择已经保存的组合。

- 默认关闭。打开“自动生成”后，每个 A 股交易日北京时间 14:30 启动。
- “运行今日简报”可在交易日 09:30 后试跑，不用等到下午。
- 同一用户、组合、交易日只建一份任务，手动与自动共用幂等键。重复点击读取原任务，不再次收费建单。
- 任务完成后点“查看与追问”，进入已有研究报告和带原始证据的追问流程。
- 关闭开关只阻止以后自动建单，不取消正在执行的任务。失败记录保留，不会因刷新页面自动重试。

电脑必须保持唤醒、联网，FastAPI 和对应 Worker 必须运行。程序不是系统闹钟，也不借助 Codex 自动化。
启动窗口为 14:30（含）至 14:40（不含）：短暂重启可以补建，错过窗口不在晚上突然补跑。
14:30 是开始时间，不是保证报告完成的时间。已受理的任务受执行队列、来源耗时、模型额度限制。

## 一次执行经过哪些步骤

1. 原 Cron 线程每分钟检查数据库中的开关，将时间转换为 `Asia/Shanghai`。
2. 用现有 XSHG 交易日历排除周末和节假日。日历越界则停止，不按周一至周五猜测。
3. 创建 `portfolio_research` Job，复用 SQL 唯一幂等键、Outbox、执行租约、Worker 和模型用量账本。
4. 刷新本组合持有基金的正式净值，再同步市场事件、热点、全市场成交额和盘中指数。
5. 保存每个来源的结果与时间。热点最多补 30 条新向量，缓存可复用；剩余报道单独保留，并注明尚未完整聚类。
6. 检查关键数据日期，冻结不可变研究快照，再进入既有 LangGraph 组合研究和模型综合。
7. 保存报告、引用、缺口和运行状态。前端只轮询数据库，不在每次 GET 时重新调用模型。

## 数据口径与边界

- **基金净值不是盘中估值。** 本项目当前使用最近正式披露的净值及其日涨跌，14:30 通常仍是前一披露日。没有新增基金实时估值源。
- **指数行情单独标时。** 当日、未过期的指数才进入判断，不把指数涨跌当基金的真实收益。
- 全市场成交额是现有来源的分页聚合，不是同一毫秒的交易所结算统计。
- 热点表示报道关注度，不代表买卖意向、资金布局或未来收益。不自动采集小红书。
- 新闻/热点等可选来源失败可降级，缺口随报告保存。缺基金有效净值、所有指数均过旧或日历无法核验时，不进入研判模型。
- 当前净值检查允许至多两个已结束交易日的披露滞后，报告保留真实日期；这不是所有 QDII、货币基金或特殊产品的统一披露规则。
- 现有历史风险指标仍保留自己的观察区间，不冒充今日盘中风险测量。
- 模型失效时原研究流程可生成**规则回退**，页面不会将其标成 AI 成功。
- 模型和自动简报的 Embedding 请求共用当前用户的预算/并发治理；超时未返回用量记“待确认”，不是零费用。
- Job 幂等不等于供应商请求绝对只执行一次。请求已发出但进程退出等不确定窗口，仍依赖原有用量待确认机制。

## 模块

| 文件 | 职责 |
| --- | --- |
| `app/services/daily_briefings.py` | 开关、交易日判断、每日幂等任务、历史状态 |
| `app/services/daily_briefing_data.py` | 数据刷新断点、新鲜度检查、事实引用 |
| `app/routers/daily_briefings.py` | 当前用户的 GET / PUT / POST 接口 |
| `app/services/cron_scheduler.py` | 原调度线程的领域回调 |
| `app/services/job_runtime.py` | 研究 Job 前置数据准备，已有快照则不重抓 |
| `app/services/portfolio_research_graph.py` | 复用研究图并冻结简报数据 |
| `app/services/portfolio_research_interpretation.py` | 将新事实送给模型，校验引用和输出 |
| `app/static/daily-briefings.js` | Web 独立页面，开关、进度、历史、报告入口 |

新增表 `portfolio_daily_briefing_policies` 仅保存策略，任务和报告仍在原表。
本地自动建表；使用 Alembic 的环境执行 `alembic upgrade head`，新增 revision 为 `92b7d631ea04`。
小程序保持不变。本轮不引入新调度框架、通知服务或自动交易功能。

## 验证

```bash
conda run --no-capture-output -n dl python -m unittest tests.test_daily_briefings tests.test_cron_scheduler tests.test_market_event_clusters -v
node --test tests/frontend/daily-briefings.test.cjs
```

测试采用临时 SQLite、固定时钟、假行情和假模型，不采集真实资讯，也不消耗模型额度。
覆盖默认关闭、节假日/越界、北京时间、重复与并发触发、身份隔离、数据过期、恢复复用、报告追问及前端迟到响应。
真实供应商是否可用、当天报告效果，需要开启前手动运行一次再检查；不要把本地替身测试说成外部供应商实测。
