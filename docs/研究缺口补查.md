# 研究缺口补查

## 这轮解决什么

原来：研究计划 → 读取一轮证据 → 检查充分性 → 模型解释。

现在：研究计划 → 读取证据 → 检查缺口 → 有限补查 → 重新检查 → 模型解释。

不是重新写 Agent Loop，也不是再加一个猜测数据的大模型。模型负责提问、选择综合研究工具和解释；Python 根据明确的缺口调度已有业务服务。

## 页面用法

1. 进入「AI 助手」，选好基金或组合，发送「请全面分析当前基金（或组合）」。
2. 默认只读取保存的数据。失败的本地读取最多补读一次，不会因为证据不足自动联网。
3. 需要检查过旧或缺失的持仓时，勾选输入框下方「本轮补查公开持仓披露」，再发送「补查后全面分析当前基金」。勾选仅作用于本次发送，发送后自动取消。
4. 展开回答下方「证据检查与补查」，查看实际动作、前后覆盖变化、失败原因和仍缺的证据。历史会话保留本轮记录，不会随今天的数据变化而改写。

「重试」按钮会重试原来的授权请求；手动重新发送则需要重新勾选。切换/新建会话会清除尚未发送的勾选。终端侧栏没有这个开关，不会借用完整助手的勾选。

## 缺口分流

| 缺什么 | 怎么处理 |
| --- | --- |
| 投资期限、能接受的亏损、近期用款条件 | 复用本会话投资背景，只补问还缺的个人条件 |
| 持仓披露缺失、过旧或无可用明细 | 本轮授权后，检查 AKShare / 东方财富公开定期披露 |
| 已有新鲜季报但只披露部分持仓 | 保留覆盖限制，不把多抓一次当作能取得实时全部仓位 |
| 净值、业绩基准、市场状态、事件的缺口 | 重读失败的本地分支；本轮未接这些外部补查适配器，仍用原有手动同步入口 |
| 久期、信用利差等尚未支持能力 | 明确说明能力限制，不能靠重复抓取或模型猜测补齐 |

零条有效事件是合法查询结果，不是“查失败了”。公开披露刚抓到，也不等于基金现在的实时仓位。

## 主要模块

| 模块 | 职责 |
| --- | --- |
| `app/schemas.py` 的 `AgentChatRequest.research_refresh` | 默认 false 的单次授权 |
| `app/services/tool_agent.py` | 每次聊天创建独立补查预算，整个工具循环共享 |
| `app/services/agent_chat_runtime.py` | 在已有幂等请求 JSON 中先保存已用预算，失败重试/重建服务后不会再抓相同来源 |
| `app/services/financial_research_repair.py` | 缺口分流、预算、动作去重、重查后重新检查充分性 |
| `app/services/fund_disclosure_fetch.py` | 固定子进程复用 AKShare Provider，超时终止抓取；不执行任意 shell |
| `app/services/financial_research_brief.py` | 复用原风险/穿透/事件业务分支，生成新旧证据检查结果 |
| `app/services/context_compactor.py` | 压缩工具结果时仍保留补查记录，防止模型丢失失败和日期限制 |
| `app/services/comprehensive_agent.py` | 将轻量轨迹存入助手消息 `run_metadata.research_repairs` |
| `app/static/research-repair.js` | 单次授权和可展开的补查记录，不从模型文案猜测执行状态 |

## 次数与时间限制

- `MAX_REPAIR_ROUNDS = 2`：一次聊天全部综合研究工具共享两轮。一次失败分支的集中本地重读算一轮，一只基金公开披露检查算一轮。
- 同一基金同一轮聊天不重复抓取；组合按当前持仓权重从高到低补查。最多补两只，不代表已更新整个组合。
- 浏览器「重试」复用原幂等键，已用预算不会重置；回答失败前已经尝试的来源不重复抓取。若进程恰好在预留名额后中断，名额仍视为已用，避免重复访问。自己调用 API 时也需要传入并复用 `idempotency_key` 才能获得跨请求保障。
- 输入缺口筛选只复用本轮已取得的披露和组合 `fund_reports`，不在计数之外再次查询失败来源。
- `DISCLOSURE_TIMEOUT_SECONDS = 25`：每只基金的公开 Provider 抓取上限，包含其股票/债券/行业接口及当前年/上一年回退。这不是“一次 HTTP 请求”，也不是整个 Agent 回答的耗时上限。
- 上述常量在 `app/services/financial_research_repair.py`，不是主 Agent 的 `max_tool_rounds`。
- 外部源没有新报告则记录「已检查，证据状态未变」。超时、空结果或报告期倒退时保留已有披露。成功抓取才落入现有披露 SQL 表，不新增数据库表。
- 某类资产有报告日期却没有有效明细时，也保留旧披露，不能因为另一类资产正常就把旧股票/债券持仓删除。界面展示实际来源和补查前后披露参考日期，覆盖分数不变时仍能看见日期变化。
- 取消后禁止继续补查/落库；已提交的公开披露更新不回滚。取消中的子进程最多继续到上述抓取超时。
- 固定数据评测模式禁止外部补查，即使请求勾选了授权。

## 离线回归

在项目 Conda 环境中运行：

```bash
python -m unittest tests.test_financial_research_repair tests.test_financial_research_brief tests.test_financial_research_planner tests.test_investment_context -q
node --test tests/frontend/research-repair.test.cjs tests/frontend/investment-context.test.cjs
```

测试覆盖：默认不联网、授权后旧季报变新季报、同报告不重复、公开源失败、保留原事实、只补读失败分支、用户信息与公开数据分流、组合权限和预算、并发隔离、LangChain 线程上下文、取消不写库、超时、SQL 记录和前端转义。

自动测试使用假公开源和临时 SQLite，不验证当前外部源的可达性，也不调用真实 DeepSeek。真实接口仍可能限流或没有新报告，界面应保留并解释这种状态，而不是承诺每次都补齐。
