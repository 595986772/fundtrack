# 自然语言组合约束求解

## 怎么测试

打开 `http://127.0.0.1:8000/#portfolio/optimizer`，先选择已有组合。

1. 输入：`债券类基金至少40%，单只基金不超过60%，单边换手最多20%，帮我降低组合历史风险。`
2. 点击“AI 整理条件”。这里会调用已配置的聊天模型，但只提取条件，不计算权重。
3. 核对基金类型、原权重、冻结时间以及三个数字。模糊要求（如“不大幅调仓”）应留空、要求补充。
4. 勾选确认，点击“确认条件并求解”。查看候选权重、逐项校验、历史CVaR、换手和平均日收益权衡。
5. 下方压力曲线比较的是原配置选出的同一历史窗口，候选方案没有重新挑时间。
6. 点击“AI 解读”会把已保存草案编号填入助手输入框；发送后模型通过只读工具解释结果。
7. 刷新页面后点击“读取草案记录”，选择原来的 `alloc_...`。不会自动重新调用模型、采集或求解。

无解测试：在只有两只基金的组合中要求每只不超过40%。非负且合计100%是硬边界，系统应说明最多只有80%，而不是生成虚假方案。

当前模拟组合若只有一只债券基金，要求“债券至少40%，单只最多35%”同样无解：这两条不能同时满足。

其他测试：换手上限0应不调仓；编辑条件会撤销勾选；输入“新增一只基金/保证未来亏损不超过10%”应标记不支持，不能静默忽略。

## 工作流

```text
前端自然语言 -> POST allocation-drafts -> 模型结构化提取
                                     -> 保存待确认草案、基金分类、行情指纹
前端核对并确认 -> POST {draft_id}/confirm -> SciPy HiGHS线性规划
                                         -> Riskfolio独立核对CVaR与约束复核
                                         -> 压力沙盘沿用冻结净值和原窗口
                                         -> 保存一次确认结果 -> 前端表格与曲线
AI 解读 -> 原Agent Loop -> get_portfolio_allocation_tool -> 模型解释证据与权衡
```

聊天入口也支持 `draft_portfolio_allocation_tool`：主模型通过Tool Calling填写结构化条件，不再额外调用一次提取模型。后端覆盖用户身份、组合身份和原始问题；模型不能指定确认状态。

Agent只拥有草案/读取工具，**没有确认求解工具**。用户在聊天中说“确认”也不会自动调用确认接口，需到组合页面核对。产品工具白名单不因这个功能而增加文件写入、shell或交易权限。

## 关键模块

- `portfolio_allocation_contracts.py`：草案允许数字留空，确认必须是0到100的有限数字；拒绝额外字段。
- `portfolio_allocation.py`：模型提取、分类冻结、SQL读写、归属检查、确认版本、幂等、复用压力报告。
- `portfolio_allocation_solver.py`：实际搜索可行权重、最小化风险、诊断不可行条件；不调用模型。
- `portfolio_allocation_tools.py`：复用同一业务服务，删去逐点曲线后把结果与事实编号给Agent。
- `portfolio-allocation.js/.css`：独立组合功能页；表单、草案、错误、历史、确认和结果展示。
- `portfolio_allocation_drafts`：SQLite/PostgreSQL表。保存原始问题、提议条件、分类依据、原情景编号、确认条件和结果。迁移版本 `e218f307c941`。

草案和结果只用于研究，不修改真实持仓或交易流水。完成结果不覆盖，修改条件需新建草案。相同草案、相同确认重复提交返回原结果；不同条件不能覆盖已经完成的确认。

## 算法与边界

这一版优化的不是未来收益、未来亏损或历史最大回撤，而是**历史单日95% CVaR**：最差5%日收益对应的平均损失，样本尾部不是整数时按比例计入。CVaR可为负值，不截为零。

设 `R` 为冻结日收益矩阵、`w` 为基金权重、`z` 为损失阈值，求解：

```text
min z + sum(u) / (0.05 * 样本数)
u[t] >= -R[t] @ w - z
u[t] >= 0
sum(w) = 1, w >= 0
债券基金权重之和 >= 用户下限
每只基金权重 <= 用户上限
sum(abs(w - 原权重)) / 2 <= 用户单边换手上限
```

使用SciPy的HiGHS求解这个线性规划，不是让模型猜权重再检查。Riskfolio的`CVaR_Hist`独立复核。相同最优风险下，再最小化换手，风险容差为 `1e-8` 个百分点。数学接口参考 [SciPy HiGHS文档](https://docs.scipy.org/doc/scipy/reference/optimize.linprog-highs.html)。

无解时用删除过滤，找到一个不可约冲突子集，并同时说明固定基金池/满仓/长仓这些硬条件。它不保证枚举所有冲突，也不计算最小放宽幅度；系统不会自动放宽。超时或数值失败不冒充“无解”。

特别注意：

- 债券类基金按档案`fund_type`判断，不按名字，也不是穿透后的债券持仓比例。未知类型在有债券最低要求时阻止求解。
- 当前只支持三类数值约束。额外需求需改写或另做扩展，不能当作已执行。
- 自然语言提取仍可能理解错误，所以原文、模型提议与用户最终确认数字同时保留；这不是语义正确性的自动证明。
- 至少60个完整共同观察日。已识别的缺日跨期收益被排除；共同缺失日期仍受原数据源覆盖限制。
- 优化使用全部有效历史日收益；压力测试使用原组合选出的最差连续窗口。两者目标不同，CVaR改善不保证压力回撤或其他指标改善。
- 都是样本内分析，不是样本外效果验证，存在过拟合风险。均值是历史平均单日收益，不是预测或年化收益。
- 固定权重每日再平衡近似，未计费用、交易限制或最低申购金额，不应把权重直接当成可执行订单。
- 没有自动行情刷新。空白情景编号时创建近12个月/20观察日的本地情景；指定编号时继承该冻结情景。修改条件默认沿用已读取的情景；清空编号后新建才读当前本地净值。
