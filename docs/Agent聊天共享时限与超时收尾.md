# Agent 聊天共享时限与超时收尾

更新时间：2026-09-30。接续第一轮的[进展与完成检查](Agent循环进展与完成检查.md)。

## 解决什么问题

轮数不多不代表等待时间短。模型、数据来源和重试如果各自领取新的超时额度，一次聊天仍可能拖很久。

现在 HTTP 产品聊天从协调入口开始计时，排队、会话准备、业务路由、工具读取、模型重试和最终整理共享同一个截止时间。下一轮不会把倒计时重新设回 120 秒。

```text
接收聊天 -> 等会话锁 -> 准备历史/投资背景 -> 路由
    -> 模型决定 -> 工具查询 -> 模型再决定
    -> 最后阶段停止新查询，只整理已有资料
    -> 保存回答与诊断 -> SSE 输出
```

## 默认规则

```dotenv
AGENT_CHAT_BUDGET_ENABLED=true
AGENT_CHAT_TIMEOUT_SECONDS=120
AGENT_CHAT_FINALIZE_RESERVE_SECONDS=20
```

这些是后端配置，不让模型或用户的工具参数修改。更改后需重启服务；配置入口是 `app/config.py`，不必修改主循环。

- 正常业务查询使用前 100 秒以内的剩余时间，不是每一步都能运行 100 秒。
- 若在轮次边界发现查询时间用完，停止新工具调用，只允许无工具整理使用最后的预留时间。
- 若某个等待中的工具或模型已超时，不再为它额外调用一个“解释失败”的模型，而是生成确定性的完成范围与缺口说明。
- 请求尚在排队或准备上下文时就超时，返回明确的时间预算错误，不保存一条冒充已完成分析的问答。
- 已进入 Loop 的部分结果可以保存回会话，`stop_reason=time_budget_exhausted`；同一幂等键重放这份结果，不重新调用模型。用户想再执行应重新发送，使用新请求标识。
- 用户主动停止与超时不同：取消向上传播，不把取消转换为成功回答，也不追加一条超时回答。

例如并发查两只基金，一只风险数据已返回，另一只查询超时。系统会保留第一只的工具回执，说明资料已返回但整体分析/校验未完成，不会生成“两个都查好了”的结论。

## 技术如何结合

### 一只共享时钟

`ChatExecutionBudget` 用单调时钟计算绝对截止时间。`ContextVar` 在协程和框架线程池之间传递同一个对象；嵌套阶段取较早的截止时间，不能通过重试或进入子步骤获得新预算。

每个阶段通过 `chat_stage()` 调用工厂函数：时间已耗尽时，连待执行的协程都不创建。用 `asyncio.timeout()` 取消超时等待，同时保留阶段、状态和耗时。

### 复用已有模型恢复与账本

`ModelRecoveryService` 取显式截止时间与聊天截止时间的较小值，重试退避、上下文恢复和续写仍在同一预算内。季报原有的专用预算也保留，取更严格的一层，不延长它。

`ModelPermit.check()` 在排队和真正请求供应商前检查聊天阶段。尚未发出请求就超时，不会开始模型生成；请求已经发出但未返回 Token 时，沿用 SQL 账本的“用量待确认”，不当作零费用。

### 保留部分结果并正确取消

并发工具在各自成功返回后立即登记回执，而非等待整个 `gather` 成功。某一路到期后，取消其余等待协程并回收，避免它们在主循环已经结束后继续推进。

超时答案不使用未校验的模型草稿，只列出已返回资料的范围和待补齐/核对事项。第一轮的完成清单仍检查模型实际保留的工具消息，未被模型读到的并发结果不冒充已经完成分析。

会话锁等待期间超时，会释放本请求实际拿到的锁，不能释放其他请求的锁，也不能遗留锁引用阻塞后续聊天。

## 重要边界

**120 秒是分析工作的执行预算，不是承诺 HTTP 一定在第 120 秒关闭。** 费用结算、必要的授权复核、锁释放和最终短事务需要正确完成；不能因为倒计时而留下错误账本，或让“已提交消息”被标失败后重复写入。SSE 网络传输也不在模型执行预算内。

取消协程不等于杀死同步线程或撤回供应商请求。已经开始的同步 I/O 依赖客户端超时结束；工具线程的后续模型调用、季报检索及公开披露补查会检查阶段已关闭/到期，迟到的披露刷新不再落库。本轮不是通用进程沙箱，不能强杀任意工具线程，也不声称能回滚已提交的副作用。

Celery 和本地后台 Job 使用自己的 AI 运行身份与时限，不继承这次 HTTP 聊天的倒计时。管理员开发模式、没有经过聊天协调入口的内部调用，保持原执行方式。关闭本轮开关不关闭原有权限、Token 额度、季报预算或轮数上限。

## 怎么验收

日常从原有 AI 助手发送问题即可，不需要新增按钮。正常完成仍显示原来的答案；超时显示完成范围与限制，不必专门把真实数据源弄坏来测试。

离线确定性测试更适合观察边界：

```bash
AI_CONTROL_BACKEND=memory TRACE_ENABLED=false python -m unittest tests.test_chat_execution_budget -v
```

测试用假模型、假数据源、MockTransport 和临时 SQLite，不调用付费模型，不修改真实持仓。覆盖：

- 不同步骤共享时间，截止后不启动新操作；子阶段不能延长父阶段。
- 慢工具、慢模型、资源排队、连续失败时停止继续调用。
- 并发部分结果保留、预留时间无工具收尾。
- 用户停止不会保存成功/超时回答，会话锁释放正常。
- 迟到的工具线程不能再启动模型调用或提交披露刷新。
- 模型已发出后的未知用量仍保留待确认，执行槽位被回收。
- 部分结果持久化、幂等重放及 SSE 正文/诊断交付。

`run.execution_budget` 和助手消息的 `run_metadata.execution_budget` 保存预算、剩余时间、触发截止的阶段与各阶段耗时；现有运行观测 `metrics` 同样保存。它是执行诊断，不是用量或费用账本。阶段有嵌套，耗时不能直接相加当作总时长。
