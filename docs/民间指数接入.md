# 宝妈与韭菜指数接入记录

## 当前范围

页面入口：市场 → 情绪指数（`/#market/retail`）。只保留宝妈和韭菜两项，
不增加个股明细、综合评分、自动交易、社媒采集或定时抓取。

- 韭菜指数使用「冷西西韭菜50」。读取作者公开发布的理论指数，不是实际账户净值，
  也不是 0-100 情绪分。已接入点位、近1/5/20交易日、近30日、近3个月涨跌和三个月曲线。
- 宝妈指数目前选择的是 `mihang123/mom-index` 公开框架 v0.1。仓库说明其数据为合成演示，
  没有现成真实指数接口，因此页面明确显示「未接通真实数据源」。没有把演示数据写入数据库，
  也没有在用户确认之前替换为 FundScope 自建算法。此项仍待指定真实发布源。

## 数据流程

1. 打开页面通过 `GET /api/v1/market/retail-indices` 读取数据库缓存，无外网访问。
2. 点击右上角更新，通过 `POST /api/v1/market/retail-indices/refresh` 读取一个固定公开文件。
3. `app/services/retail_indices.py` 校验指数身份、基点、有限正数、日期顺序与数据末日。
4. 按作者的 close 序列计算涨跌，保存到 `retail_index_cache` 表。保留来源 SHA-256、
   数据日期、抓取时间和错误；失败或来源回退不会覆盖旧快照。
5. `get_retail_indices_tool` 读取同一份缓存，但不发送完整曲线给模型，不自动联网刷新。
   产品模式拥有 MARKET_READ 权限，Prompt 明确区分点位、百分比、缺失和历史缓存。

刷新限频一分钟；没有常驻自动刷新。超过四个自然日没有新观测显示「数据偏旧」，
这是保守的提示阈值，不是交易日历判定。页面始终显示实际末日。

## 计算口径

`涨跌幅 = (末日点位 / 起点点位 - 1) × 100`。API 的 `value_pct` 已是百分比。
近30日按自然日、近3个月按自然月，取目标日当天或之前最后一个观测点；
1/5/20窗口按发布序列的交易观测点回看。无起点就显示历史不足，不补零。

三个月曲线保留实际观测日期，不补周末。发布日之前标为模拟回测，之后标为公开规则发布后表现。
上游规则研究不代表已经独立验证了预测能力。

- [作者公开序列](https://indices-toocoldcc.pages.dev/data/bagholder50.json)

只实现公开数据格式适配，没有复制或运行上游采集器、Skill 或反检测代码。
没有下载订阅内容，没有接入小红书账号、Cookie、API Key，也没有调用付费模型。

## 手动验证

打开情绪指数页面，点右上角更新图标。韭菜50应显示日期、点位和走势；宝妈应仍然
明确缺失。切换市场功能只显示对应面板，不堆叠其他功能。刷新浏览器后指数仍从数据库恢复。
在 AI 助手询问「查一下宝妈指数和韭菜指数」可触发只读工具；本轮未进行付费模型端到端调用。
