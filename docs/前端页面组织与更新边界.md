# 前端页面组织与更新边界

更新日期：2026-09-08

## 参考与取舍

- [Wealthfolio](https://wealthfolio.app/docs/guide/dashboards/)：总览用于浏览摘要，持仓、账户和业绩各有明确的深入入口。
- [Ghostfolio](https://github.com/ghostfolio/ghostfolio)：借鉴其组合管理产品按业务任务组织功能的方向。
- 本项目保留 FastAPI、原生 JavaScript 和已有终端配色，没有复制第三方源码，也没有迁移 React。

## 用户从哪里进入

| 工作区 | 功能组织 | 对象选择 |
| --- | --- | --- |
| 研究终端 | 行情与研判；单基金持仓分析 | 自选基金栏 |
| 组合 | 资产与业绩；风险与配置；研究与跟踪 | 当前组合选择器 |
| 市场 | 行情与资金；资讯与主题；情绪与社区 | 需要时展示关联基金选择器 |
| AI 助手 | 对话、已有研究的解释和追问 | 对话自己的研究上下文 |

桌面用左侧分组链接，手机用分组下拉选择器。URL 仍沿用 `#portfolio/stress`、`#market/news` 等，支持刷新、后退、前进和直接打开。热点没有基线时可以直接前往市场事件页。

## 代码如何组织

- `app/static/workspace-pages.js`：唯一的功能目录、分组顺序和 URL 解析。桌面与手机共用，不维护两份菜单。
- `app/static/workspace-page-host.js`：管理组合页面 DOM 生命周期，不读取业务数据。首次打开才挂载，隐藏时保留节点，换用户或组合才重建页面树。
- `app/static/app.js`：继续负责业务状态、API 调用和现有业务渲染器。`loadPortfolioPage` / `loadActiveWorkspacePage` 分派当前页面的只读请求；`renderPortfolioPage` 只组合指定页内容。
- `app/static/workspace-pages.css`：导航、页面容器和响应式结构，沿用现有令牌，不另造主题。
- 压力测试和约束求解继续由各自模块管理内部输入和执行状态，不因其他页面更新而反复卸载。

## 更新规则

原来：监控进度变化 -> 重建整个组合工作台 -> 所有表单和隐藏页一并被替换。

现在：监控进度变化 -> `renderPortfolioWorkbench({pages: ["monitoring"]})` -> 仅标记监控页 -> 正在查看才渲染，其他页 DOM 不动。

同样，风险、业绩、事件归因、决策复盘和研究结果分别通知自己的页面。重复数据通知不会替换相同内容；页面切换保留未提交输入与展开状态。更换组合不保留上一组合的输入。单基金持仓分析由独立模块管理，不依赖组合页面树。

主动再次“新建组合”会递增草稿实例编号，确保清空上一份未保存的输入。决策表单将显示的研究报告 ID 一起绑定到表单，其他页加载新报告不会悄悄改变本表单提交的证据来源。终端的资金、热点、社区标签各有按需读取入口，不依赖市场页先被打开。

风险、业绩、深度研究分别使用 `state.portfolioPeriods.risk / performance / research`，改业绩区间不会修改研究任务参数。

组合页的只读请求按用户、组合、页面和当前区间复用，失败后可重试。顶栏刷新只读取当前工作区所需数据；组合刷新会重读组合信息并刷新当前功能。切换功能不会启动行情采集、社区抓取、付费模型或求解任务。

## 如何验证

```bash
node --test tests/frontend/*.test.cjs
```

1. 在约束求解中输入草稿，去压力测试再返回，草稿应保留。
2. 运行中的研究或监控更新时，其他页面的表单不应被清空。
3. 将业绩改为 3 年，再打开风险研判，区间仍保持原值。
4. 打开市场事件，更换关联基金，仍停留在市场事件页面。
5. 手机选择功能页面、浏览器后退和前进，标题、导航和正文应一致。

## 尚未全面重构的部分

业务渲染函数和部分共享状态仍在 `app.js` 中；本轮不是完整框架迁移。市场已有独立静态面板，保留其筛选控件，只按当前路由读取数据。终端内部的图表、资讯、AI 辅助区维持现有布局。后续拆业务文件应沿上述页面边界逐个迁移，不能恢复全局重绘。
