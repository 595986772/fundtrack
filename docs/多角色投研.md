# 多角色基金投研

## 使用入口

Web 的 **AI 投研 → 研究报告**，选择组合、观察区间，将研究模式切换为“多角色研判”，
再点击启动。切换模式、打开报告和查看历史都不会调用模型。
如果页面正在展示旧报告，先展开“历史报告与后续研究”，在那里选择模式并重新生成。
阅读时先看最终结论与分类依据；“多角色研判”位于其后，展开“研究员独立观点”或
“一次相互质询”可核对完整过程。查看这些内容不会重新调用模型。

默认仍为综合分析。2026-09-29 起，Web 可填写研究问题并选择自动、配置解释、季报策略比较、综合或多角色。
聊天工具按当前问题创建受控计划；旧客户端、小程序的缺省请求与每日简报保持综合模式。
各路径与有限补查的具体边界见 [RAG 与组合工作流升级](RAG与组合工作流升级.md)。
已完成的旧报告不需要迁移；重新选择多角色并创建一次研究，才会出现新的角色结果。

## 通俗理解

原来是“程序整理材料，一个模型综合解释”。新模式先让机会研究员和风险研究员分别
看同一份材料，再让他们各回应对方一次，最后交给综合研判员整理。不强迫看多/看空，
也不以谁支持的人数多作为正确性证明。

```text
冻结输入 → 五路确定性数据 → 模式选择
                             ├─ 轻量 → 原有综合模型 → 报告
                             └─ 多角色 → 机会 / 风险独立分析
                                         ↓
                                      双方各回应一次
                                         ↓
                                      综合者 → 报告
```

借鉴的是 [TradingAgents](https://github.com/TauricResearch/TradingAgents) 的角色分工与
质询思想。实现使用现有 LangGraph，不导入它的 SDK，不安装另一套交易系统。这里是
受控的多角色工作流，不是每位研究员都能无限抓数据、调用任意工具的自主交易 Agent。

## 数据与工程边界

- 模式写入 Job payload 和图状态；恢复同一 Job 时不能换模式。
- 所有角色读取同一份不可变研究快照。期间不刷新数据、不抓小红书、不执行交易。
- 每条观点引用指标或证据白名单；具体金融数值仍由 Python 解析。
- 多角色正文不允许重写数字（原样基金名称除外），即使某个数值在别的指标里出现，
  也不能拿它冒充当前指标。这样避免把持仓权重错误说成收益率。
- 质询必须完整覆盖对方已有观点，不能引用不存在、遗漏或重复的 claim_id。
- 综合报告保留质询中的分歧和各方未解决的缺口。引用校验不是语义正确性的证明，仍需人工判断。
- 共五个角色调用阶段；每阶段一次业务 invoke，超时为六十秒，输出上限为二千二百 Token。
  供应商切换遵循已有模型配置，真实请求和用量以 AI 治理账本为准，不能把角色数等同计费次数。
- 默认任务超时为九百秒。额度不足或取消向上传播；模型输出校验失败不进行无限重试。
- 必要阶段失败时，保留已校验的角色观点，但最终报告标为降级，使用现有确定性总结，
  不会把不完整结果包装为“多 Agent 已达成共识”。
- 每个角色是独立父图节点，共十三个节点进度。成功节点与并行 pending writes 随原
  SQLite/PostgreSQL checkpoint 保存，接管重试不重跑已持久化的成功阶段。
- 明确兼容上一版 v7 轻量流程的快照与检查点；升级后旧任务不会自动变成多角色任务。
- 无法承诺模型侧恰好调用一次：供应商已响应而检查点尚未落盘时崩溃，仍可能重复调用。
  这类用量由原任务预算和治理账本约束，不会另开预算绕过限制。

## 代码导航

| 文件 | 职责 |
| --- | --- |
| `app/services/portfolio_research_committee.py` | 三种角色的契约、模型调用、引用验证、质询完整性与降级 |
| `app/services/portfolio_research_graph.py` | 角色节点、并行汇合、模式路由与检查点 |
| `app/services/portfolio_research_interpretation.py` | 复用的指标目录、证据作用域与最终报告校验 |
| `app/services/background_jobs.py`、`job_runtime.py` | 模式持久化、进度、超时和 Worker 执行 |
| `app/services/portfolio_agent_tools.py` | 将原报告的角色意见与证据带入后续对话 |
| `app/static/research-committee.js` | Web 中的模式选择及报告展示辅助 |

## 如何测试

确定性测试不会访问 DeepSeek 或外部金融数据源：

```bash
conda run --no-capture-output -n dl python -m unittest \
  tests.test_portfolio_research_committee \
  tests.test_research_committee_jobs \
  tests.test_committee_context \
  tests.test_portfolio_research_graph \
  tests.test_reliable_research_checkpoints -v
```

页面手动测试会产生真实模型用量：

1. 选择有完整历史数据的组合，新建一次多角色研究。
2. 看进度中的机会、风险、相互回应与综合阶段。
3. 报告中核对两方观点、质询对象、指标值和来源，分歧不能被隐藏。
4. 刷新页面再打开同一报告，不应新建 Job 或重新分析。
5. 点击继续追问，问“风险研究员反对的依据是什么”，应基于原报告证据回答。
6. 新建轻量研究、查看已有每日简报，确认不会意外进入多角色模式。

这些测试证明编排、数据边界与恢复机制，不证明多角色比单模型更准确。效果比较需要
在相同快照和问题下单独记录答案质量、耗时、Token 用量，后续再做对照评测。
