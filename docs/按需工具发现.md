# 按需工具发现

## 这轮做了什么

以前：路由器在请求开始时选择工具，选漏了以后，本次问答通常不能再补进来。

现在：仍然由路由器选首轮工具。对复杂的基金、组合和市场只读问题，额外提供一个 `search_tools_tool`。模型发现缺少能力时，可以描述需要什么，后端从已授权目录查找工具，在下一轮加载其参数定义。

这是基于 LangChain `StructuredTool` 和现有 Agent Loop 的本地实现，不是接入 Anthropic 的专有 Tool Search 接口。仍然使用当前配置的 DeepSeek。目录搜索本身不调用另一个模型、不需要 Embedding 或新数据库；模型决定是否搜索以及如何使用结果。

```text
用户提问
  -> 现有路由选择少量业务工具
  -> 模型读取数据，判断是否还缺少能力
  -> search_tools_tool("半导体近期新闻政策")
  -> 后端过滤权限、匹配目录、检查次数和 Schema 大小
  -> 本轮所有 ToolMessage 回填完毕
  -> 下一轮更新 bind_tools、执行映射及相应业务 Prompt
  -> 模型调用新工具取得数据
  -> 根据实际证据回答，或说明仍然缺少什么
```

**搜索工具只找到“能干什么”，不等于已经取得数据，更不是已经得到金融证据。**

## 从页面怎么试

1. 打开网页版的 AI 对话入口，选中一只基金，新建会话。
2. 提问：`为什么这只基金最近回撤明显？缺少证据时再补查。`
3. 查看运行过程。若模型判断现有工具不够，会先出现 `search_tools_tool`，然后显示“已更新本轮可用的只读工具”，再调用补入的工具。
4. 对照提问：`这只基金的最大回撤是多少？`。这种简单查询不加载发现入口，保持原来的快速流程。

不是每次复杂提问都必须搜索；原工具已经足够时，直接回答才是正确行为。固定的“全面研究”、季报 RAG、组合研究任务有专用流程，这轮没有改为动态发现。基金或组合没有选定时，也不会通过工具目录猜测私人组合。

如果需要更明确地观察路径，可在选中基金后提问：`请先用 get_fund_risk_tool 读取风险；如果缺少解释原因的能力，再搜索可用的新闻工具并读取相关证据。不要自行刷新数据。` 是否继续搜索仍由模型根据已有信息决定；确定性的流程验证见下方离线测试。

数据缺失或过旧时，工具发现不会自动解决数据问题。补入的工具仍读取已有快照；保持原来的手动更新入口和公开披露补查授权机制。

## 约束和配置

| 配置 | 默认值 | 含义 |
| --- | --- | --- |
| `AGENT_TOOL_DISCOVERY_ENABLED` | `true` | 关闭后恢复原工具路由行为 |
| `AGENT_TOOL_DISCOVERY_MAX_CALLS` | `2` | 每次问答的搜索次数；配置最多允许 4 次 |
| `AGENT_TOOL_DISCOVERY_TOP_K` | `3` | 每次最多返回 3 项；可调小，不允许调大 |
| `AGENT_TOOL_DISCOVERY_MAX_SCHEMA_CHARS` | `16000` | 工具参数定义序列化后的总字符上限，不是 Token 数 |

- 只在产品模式、复杂只读路由且至少还有两个工具轮次时提供入口。开发者/MCP、写操作、带季报或研究任务上下文的请求不启用。
- 目录只包含审核过的基金、组合、市场读取工具。未授权工具不会进入搜索结果；新工具执行前仍经过原有权限检查。
- 用户身份由后端注入，当前选中的基金和组合优先于模型参数，不允许模型借搜索更换身份。
- 首轮加上发现入口就超过大小上限时，保留原路由；后来候选工具超限时，不加入该工具。
- 重复查询、无匹配和大小超限的搜索也计入次数。参数格式错误由原有校验处理，仍占用所在的主循环轮次。
- 搜索次数与已有主循环上限是两种限制，发现工具不会重置轮数。默认主循环仍为 10 轮，最后一个工具轮次移除发现入口，避免搜索到工具却没有下一轮执行机会；原来的最终整理机制保留。
- 不新增模型额度。模型决策和后续回答继续经过现有并发、超时、重试及 Token 预算治理。
- 每次问答独立创建工具池，不能把一个用户加载过的工具带给另一个用户，也不跨问答保留目录状态。

修改环境配置后需重新启动后端。这里不修改真实 `.env`，默认值已放在 `app/config.py` 和 `.env.example`。

## 从哪里看执行记录

产品聊天接口及 SSE 的最终结果中，查看 `run.tool_discovery`：

- `enabled`：本次是否允许按需发现。
- `initial_tools` / `loaded_tools`：原有工具和本次实际补入的工具。
- `searches`：查询、匹配状态、命中项、加载项与本地搜索耗时。
- `bindings`：首次及后续重新绑定时的轮数、工具名和 `schema_chars`。

轨迹也存入助手历史消息的 `run_metadata.tool_discovery` 和现有 Observation 的 `metrics.tool_discovery`，没有新增表。`route` 保留最初路由，后续补入的能力以发现轨迹为准。

首次本地测量，选中基金询问回撤原因时，原风险工具定义为 482 字符，加入发现入口后为 809 字符，同一请求下可见的全部 10 个只读工具定义合计 5579 字符。**这是该版本的一组 Schema 字符数，不是 Token、费用或延迟的节省比例**。相对于原来的窄路由，发现入口本身有开销，搜索还可能增加模型轮次；是否值得使用，要比较同题、同数据和同预算下的完成率、实际 usage、耗时与证据质量。

## 关键代码

| 文件 | 作用 |
| --- | --- |
| `app/services/tool_discovery.py` | 审核目录与检索别名、权限过滤、请求内工具池、搜索/Schema 上限和轨迹 |
| `app/services/tool_agent.py` | 在现有 Loop 的轮次边界加载工具，同时更新 Prompt 和执行映射 |
| `app/services/agent_execution_context.py` | 声明工具发现能力；它不会授予新的业务权限 |
| `app/services/agent_tool_executor.py` | 复用工具分发与可信参数注入，拒绝同轮猜测调用未绑定工具 |
| `app/services/prompt_builder.py` | 告诉模型什么时候搜索，以及“能力”和“证据”的区别 |
| `app/services/comprehensive_agent.py` / `observability.py` | 保存会话摘要和观测记录 |
| `tests/test_tool_discovery.py` | 模拟模型调用，验证加载顺序、权限、身份、预算、隔离与持久化 |

检索采用人工审核的中英文别名、工具名匹配及少量描述辅助评分。完整函数和参数 Schema 仍来自现有工具注册表，不复制实现。无匹配时返回明确缺口，不用低相关工具硬凑结果。

## 离线测试

在项目已有 Conda 环境中运行：

```bash
python -m unittest tests.test_tool_discovery tests.test_agent_routing tests.test_agent_access_modes tests.test_fund_agent_tools tests.test_market_agent_tools tests.test_agent_model_timeout tests.test_evidence -q
```

更大的回归包含旧的 HTTP/SSE 用例。如果未启动 Redis，可只对这条测试命令设置 `AI_CONTROL_BACKEND=memory`，不要因此修改部署环境的配置：

```bash
AI_CONTROL_BACKEND=memory python -m unittest tests.test_agent_runtime tests.test_recovery tests.test_mcp_tools tests.test_agent_evals tests.test_agent_feedback tests.test_investment_context tests.test_fund_report_runtime tests.test_fund_answer tests.test_fund_report_answer tests.test_financial_research_repair tests.test_ai_governance tests.test_ai_governance_integration -q
```

测试使用本地模拟模型，不请求真实 DeepSeek，也不验证外部新闻的可达性或模型实际选择工具的质量。Redis 专用测试需要独立测试 Redis，未配置时跳过。

## 本轮没有做

- 没有新增向量工具检索、外部工具市场或自动授予权限。
- 没有把所有工具都改成延迟发现，已有专用研究流程保持原样。
- 没有实现新的“大结果保存 + 按编号分页读取”协议；原有工具结果压缩仍沿用现有实现。
- 没有自动扩大调用预算、刷新行情、抓取社媒或执行交易。
