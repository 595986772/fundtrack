# Agent Loop 第一轮优化：防空转与完成检查

更新时间：2026-09-30。

这一轮不换 Agent 框架、不增加新的模型服务。只解决两个问题：**不要重复查同一份资料；不要少查了对象，却把回答当成完整结论。**

## 1. 现在如何执行

```text
用户问题 -> 原有业务路由 -> 建立本轮最低取证清单
    -> 模型决定要用什么工具
    -> 原有工具权限及任务授权检查
    -> 执行查询，或复用本次请求内相同的成功读取
    -> 再检查任务授权 -> 回填 ToolMessage -> 原有上下文压缩
    -> 检查本轮是否获得新结果
        有进展：继续
        连续 2 轮无进展：提示改查缺项或说明限制
        连续 3 轮无进展：停止工具调用，整理现有依据
    -> 模型提出最终回答
        取证清单齐全：进入原有回答出口
        有缺项且还有轮数：最多提示纠正一次
        仍有缺项：返回已取得的资料范围与缺口，不展示完整结论草稿
```

“纠正一次”是一次提示模型继续补查的机会，不是另开一个无限循环。后续模型和工具调用仍占用原来的 `max_tool_rounds`，默认 10 轮。达到上限或无进展后，沿用原有的一次无工具整理调用。

## 2. 防重复空转

### 同一次请求内复用只读结果

例如模型连续两次调用同一基金、同一区间的风险工具：第二次不用再计算，但仍返回与这次 `tool_call_id` 对应的 ToolMessage，避免破坏模型的工具消息协议。

目前只缓存六个工具：基金档案、净值摘要、历史风险、组合评估、组合业绩、组合穿透。缓存键包含用户、任务授权、任务/Agent 身份、工具名与规范化参数；省略默认参数与显式传默认值可以命中同一结果。

- 只保存在当前 `chat()` 实例中，不跨请求、用户或会话共享。
- 每次工具调用仍走权限检查；命中缓存后也检查授权是否已撤销或过期。
- 同轮并发的相同读取用锁合并，但分别保留调用回执和审计记录。
- 错误结果、过大的返回值不缓存；写入、Job 状态及模型分析不缓存。
- 遇到未纳入只读监测的工具会清空读缓存，避免后续沿用写入前的结果。
- `research_refresh=true` 时绕过这个缓存，但不扩大原有公开数据刷新权限。
- 缓存代表本次请求已经读到的结果，**不代表再次抓取了最新数据**。

### 判断进展，而不是只数调用次数

工具名称与返回内容共同生成指纹，忽略请求编号、执行耗时等观测字段；数据日期、数值和文档版本仍参与比较。

第一次成功读到资料算进展；再次拿到相同结果不算。错误不会被当作成功证据。工具发现真正加载新能力也算流程推进。

例如连续四轮查询同一结果：第一轮获得资料，第二轮开始无进展，第三轮提醒，第四轮停止。换统计区间并取得不同结果则继续，不会因为调用了同一个工具而被直接拦截。

这只是**结构化结果去重**，不是模型语义判重；不同结果描述相近事实时，不保证识别为重复。第一轮仅监测已登记的产品只读工具，不对开发者工具、写入流程和后台状态轮询套同一规则。

## 3. 完成检查的范围

| 问题 | 最低证据要求 |
| --- | --- |
| 明确给出 2–4 个六位基金代码，比较风险、波动或回撤 | 每只基金都有实际风险指标，统计区间一致 |
| 明确代码，比较经理策略、观点或季报 | 每只基金有两个不同季度的经理原文，包含文档编号、页码和证据编号 |
| 已选组合，要求解释收益与风险 | 有实际收益数字，另有回撤或集中度依据 |

检查的是压缩后仍在模型上下文里的工具结果。不会用已被删掉的审计原文偷偷补齐清单。`ok: true`、空字段、错误提示、重复的同一季度，以及尚未取得的数字都不能充当完整依据；零收益则是合法数字。

如果页面绑定了单只基金，而问题要求比较多只基金，程序会提示先取消单基金选择。它不会通过改写权限或页面绑定来强行查询其他对象。

原有综合研究工具、后台组合研究、压力测试和配置求解保留各自的专门完成协议。普通解释性问题、没有明确代码的比较、未支持的任务不强套上述清单。

**`evidence_ready` 只表示最低取证清单已覆盖，不表示回答语义、每条推断或未来收益已经被验证。** 原有单基金事实/季报引用检查继续使用；本轮多基金比较不冒充已通过单基金原句校验协议。

## 4. 如何测试和观察

在现有 AI 助手中使用，不需要新的按钮。跨基金比较先取消单基金绑定。

1. 问：“比较 110020 和 110007 的近一年风险。”应取得两只基金同区间指标；缺数据时不能直接生成完整比较。
2. 问：“比较 110020 和 110007 最近两季的经理策略。”需要本地已保存两只基金的两期季报。没有资料应说明缺口，不自动抓取或补造原文。
3. 选中一个有流水的组合，问：“解释当前组合的收益与风险。”应有收益及风险依据；专用研究工作流仍由原协议管理。

真实模型不一定会产生重复或漏查，因此正常页面测试不保证触发每条保护。确定性边界由假模型测试重现，不需要故意诱导真实模型多花费用。

现有 API 的 `run.loop_control`、SSE 最终 `result`、会话元数据和运行观测记录保存：

| 字段 | 含义 |
| --- | --- |
| `cache_hits` | 本轮相同读取被复用的次数 |
| `rounds` | 每轮是否有新结果、连续停滞次数及处理动作 |
| `required / covered / missing` | 要查什么、已覆盖什么、还缺什么 |
| `completion_status` | 不适用、证据齐备、缺资料或需澄清 |
| `completion_retries` | 是否使用过一次有限补查提示 |
| `stop_reason` | 模型正常结束、轮数上限、无进展、缺资料或需澄清 |

每条 `tool_calls` 另有 `execution_kind`，区分 `executed` 与 `cached`。页面继续使用已有阶段提示和最终回答；本轮未增加独立诊断面板。

在项目 Conda 环境执行离线测试：

```bash
AI_CONTROL_BACKEND=memory TRACE_ENABLED=false python -m unittest tests.test_agent_loop_guard -v
```

测试使用假模型、假业务来源和临时 SQLite，包括重复调用、并发去重、刷新绕过、参数变化、授权撤销、缺失证据、纠正次数、强制结束和记录持久化。没有请求收费模型，也没有改真实持仓。

本次验收：新增 32 项测试通过；两组相关回归去重后共 330 项通过，2 项需要本机真实 OpenFGA 的集成测试未启用。部分旧 SSE 测试的假结果不含任务授权，因此仅在对应测试进程关闭外层授权；另一组在授权开启状态下验证主循环、撤销及追踪。没有改动实际服务的授权配置，也没有进行真实收费模型的端到端验收。

## 5. 对照源码

| 文件 | 作用 |
| --- | --- |
| `app/services/agent_loop_guard.py` | 请求级缓存、结果指纹、取证清单与最终缺口说明 |
| `app/services/tool_agent.py` | 在主循环工具执行后和最终回答前接入控制 |
| `app/services/agent_tool_executor.py` | 在授权边界内复用成功读取，保留独立工具回执 |
| `app/services/agent_routing.py` | 明确跨基金比较时保留所需风险/季报工具 |
| `app/schemas.py` | `AgentLoopControl` 和工具执行方式字段 |
| `app/services/comprehensive_agent.py`、`observability.py` | 将轻量控制结果写入现有 JSON 记录 |
| `tests/test_agent_loop_guard.py` | 确定性单元及真实主循环集成测试 |

配置项 `AGENT_LOOP_GUARD_ENABLED` 默认开启。设置为 `false` 并重启服务，可关闭本轮新增的缓存、进展判断与完成清单；原有权限、轮数上限和业务校验不变。没有新增数据库表或依赖。

本轮不新增通用截止时间、全任务成本上限、错误分类重试或后台工作流恢复逻辑。已有相应治理仍然生效；“不再空转”和“单次调用不会超时”是两个不同问题。

后续第二轮已接入 HTTP 产品聊天的[共享时限与超时收尾](Agent聊天共享时限与超时收尾.md)，其范围和验收见单独说明。
