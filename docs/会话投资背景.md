# 会话投资背景与多轮研究衔接

## 本轮解决的问题

聊天历史里说过“三年不用、最多接受亏损 15%”，不代表 Python 研究闸门能理解历史。
现在先把用户明确说过的条件提取为结构化状态，再把同一份状态交给主模型和研究工具。
本功能是会话级业务状态，不是新建一套向量 Memory，也不是自动交易或正式风险评级。

## 数据流

```text
当前用户消息 + 当前会话最近成功保存的投资背景
  -> InvestmentContextService：有条件的结构化提取、原话校验、增量覆盖
  -> investment_context_scope：本轮独立的 ContextVar
  -> SystemPromptBuilder：主模型看到已知条件、待确认状态、上一研究问题
  -> AgentToolExecutor：短回复继续使用上一研究问题
  -> 基金 / 组合研究 Brief -> FinancialEvidenceGate：直接检查背景字段
  -> 成功回答 + 背景快照在同一消息事务中保存
  -> 前端回答下方的“本轮投资背景”可展开查看
```

持久化位置：`agent_conversation_messages.run_metadata.investment_context`。
读取时同时核对 `user_id` 和 `conversation_id`，背景不依赖最近 16 条聊天窗口。
提交时用会话 `updated_at` 做数据库原子比较：若另一请求已更新会话，本次旧回答不落库，
HTTP/SSE 返回 409 冲突提示，请重新发送。它补充现有进程内会话锁，防止旧背景覆盖新更正或清除。
新对话默认为空；旧会话不自动回扫全文生成个人档案。刷新页面或重启服务可恢复已保存条件。

## 保存内容

| 字段 | 含义 |
| --- | --- |
| `facts.horizon` | 用户自述的投资期限 |
| `facts.loss_tolerance` | 用户自述的可接受亏损或风险程度，不是基金历史回撤 |
| `facts.liquidity` | 近期是否需要赎回或用钱 |
| `facts.purpose` | 资金用途，可选背景，不强制每次追问 |
| `fund_code` / `portfolio_id` | 本次研究的页面对象 |
| `research_question` | 实际执行过的个性化研究问题 |
| `pending_fields` | 研究仍缺少哪些投资条件 |
| `needs_confirmation` | 上次更正未能确认，旧值暂不用于判断 |

每项条件保留原句、来源用户消息 ID 和更新时间。模型不负责换算风险分数或自行补齐空值。
新的明确条件覆盖同字段旧值；其他字段保留。明确换另一笔资金时重置旧背景，再保存新条件。

## 使用与验收

在前端 AI 助手中保持同一个会话，选择基金后依次发送：

1. `这笔钱三年不用，最多接受亏损15%，用于养老。`
2. `这只基金适合我吗？请结合我的情况分析。`
3. `更正一下，最多只接受亏损5%，其他不变。`
4. `请根据我的情况重新分析这只基金。`
5. `清除本次投资背景`

观察回答下方的“本轮投资背景”：第 2 轮应沿用第 1 轮条件；第 4 轮应使用 5% 而不是 15%；
第 5 轮应显示已清除。历史消息仍显示当时的快照，不会改写历史。清除背景不等于删除聊天；
删除会话才会一起删除消息及其快照。

另开新会话，直接问 `这只基金适合我吗？`，研究应指出缺少用户背景。
再补答 `三年不用，能接受亏损10%。`，工具应继续上一研究，不再问已知的期限和承受能力。
实际是否需要补查其他金融证据，仍由研究结果决定；背景完整不等于投资一定合适。

## 模型调用与边界

- 可能包含个人条件、更正或短回复时，增加一次无工具、低温、关闭思考的结构化提取。
- 沿用现有模型配置；这一辅助调用仍可能产生 API 费用，不代表免费。
- 普通问候和不涉及个人条件的查询不额外提取；提取等待上限为 10 秒，不循环重试。
- 超时、格式错误、出处不在原话中时显示待确认，不偷偷使用更正前的条件。
- 假设、别人情况、行情指标不应成为个人背景；语义提取仍可能出错，所以前端公开原话便于更正。
- 不跨会话自动继承，不从新闻、RAG、助手建议或压缩摘要中生成用户条件。
- 普通聊天的 Prompt 与两个综合研究 Brief 使用状态；独立 REST 无会话调用保留原有行为。
- 本轮没有把状态扩展为全账户档案，也未把它写入后台八阶段研究的冻结快照。
- 背景辅助调用暂未合并到原有主 Agent 的 Token usage 统计，不能把该统计当作完整账单。
