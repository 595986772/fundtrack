# 基金季报 RAG 与两期比较

更新：2026-09-29。新增的检索排序、组合共享证据与按需补查见 [RAG 与组合工作流升级](RAG与组合工作流升级.md)。

## 用法

1. 网页选中一只基金，进入“季度报告”；小程序进入基金详情，点击“季度报告与两期对比”。
2. 首次点击“同步最近两期”。后台查公开基金公告，下载最近两个不同季度的完整 PDF，保存原文并建立向量索引。只同步当前基金，不会修改持仓。
3. 查看资产配置变化，点击比例旁的原文入口核对 PDF 物理页码。页码是阅读器页数，不根据正文中的页脚数字猜测。
4. 点击“AI 对比分析”，进入现有研究对话。可以修改草稿；按发送后才调用 DeepSeek。
5. 继续问“经理的指数化投资策略变了吗”“这项变化有哪些局限”。同一对话沿用同一基金的两份文档，不偷换为新同步的季度。
6. 点击“查看引用季报”返回对应版本。更换研究对象或开始新话题会解除引用。

本次已用 110020 的 2026-Q1、2026-Q2 公开报告跑通同步。网页为 `http://127.0.0.1:8000/#assets/fund/reports`；小程序预览为 `http://127.0.0.1:8000/mini#/pages/fund-reports/index?code=110020`。

微信开发者工具需要重新编译 `miniprogram/dist` 再进行真机调试。H5 预览不等于微信真机验收。

## 数据流

```text
点击同步 → FastAPI 校验身份 → 持久化 fund_report_sync Job
  → 东方财富公告列表 → 最近两个不同季度的 PDF
  → pypdf 核对基金/季度、按物理页提取原文
  → SQL 存文档版本、页码文本和标准表格数字
  → Qwen embedding → 独立 Chroma 集合

AI 提问 → 验证会话和两份文档编号 → 按基金、文档 ID 检索
  → 语义召回 + 中文 BM25 → RRF 融合 → 可配置精排（未配置则不调用）
  → 分季度配额 + 经理运作分析章节 + 资产表主项原文
  → 按当前问题选择轻量资产表上下文或完整研究上下文（保留原始工具结果）
  → 明确季末日期/披露日、数字/横杠/缺行/解析失败
  → Python 只比较可靠数字，为实际上下文中的原句生成不可变编号
  → DeepSeek 在原总结轮返回逐主题解读、原句编号、披露对照/推断分类与推断限制
  → 核对编号/季度/阅读范围，必要时无工具修正一次
  → Python 附上实际可见的前后原句，生成阅读范围、数字与页码链接，渲染最终正文
  → 保存问答与 fund_report_reference → 下一轮沿用同一版本
```

这一轮没有重写 Agent Loop、长期 Memory 或通用知识库。季报工具属于基金产品模式的只读能力，没有给模型新增下载或交易权限。

## 保存与费用

- PDF 备份位于 `data/fund_reports/fr_<内容标识>.pdf`，已加入 Git 忽略。
- 数据表为 `fund_report_documents`。同一基金、同一文件哈希重复同步不会新建文档；更正版本不覆盖旧文档。
- 向量使用现有 `CHROMA_PERSIST_DIR` 下独立集合，集合名包含模型配置签名，不会覆盖普通 RAG 知识库。切换 embedding 模型或维度后需手动同步建立新索引。
- 已有 Qwen embedding 与 DeepSeek 配置可直接复用；没有新增 API Key。每批 embedding 最多 10 段，检索问题只向量化一次，再分别查询两期文档。
- 普通打开页面、切换报告、看原文和查看比较都不调用模型。同步可能产生 embedding 费用；发送问题可能产生 embedding 和 DeepSeek 费用。
- 季报结构化总结使用原来的模型轮次，不增加第二个分析模型。格式或引用不一致时最多修正一次，
  不开放工具、不联网补查；成功返回的修正用量计入本轮Token，仍失败就不展示模型草稿。
  超时/取消未取得供应商用量时，已记录Token不代表完整账单，不能理解成失败调用免费。
- 索引失败时原文仍保存，页面标明“关键词检索”，工具明确回退原因，不冒充语义检索成功。

## 当前边界

- 首版支持公开、非加密、文本型季度报告，单文件最多 10 MB / 80 页；暂不做扫描件 OCR、半年报和年报比较。
- Python 只解析标准“5.1 基金资产组合情况”的总资产比例，不混用净资产口径。不支持的表格显示未提取，不补零。
- 比例变化用 Decimal 算百分点。没有前期数据就不计算差值；不能从比例变化推断买入、清仓或真实交易流水。
- ETF 联接基金的“基金投资”不是目标 ETF 的全部穿透持仓；A/C 等份额共享报告中资产信息，不混算各类份额业绩。
- 经理观点是历史陈述，模型的解释不是量化事实或收益保证。仅两份披露不能判断当前实时仓位。
- 检索有明确的文本预算，不等于模型读完全部 PDF。证据不足时允许回答“不可比”或“未找到”。
- 公告站点可能限流或变更格式。同步失败保留旧文档，用户可稍后手动重试；没有隐式后台采集。

## 经理观点与归因边界

- 章节提取兼容“基金投资策略”和“基金的投资策略”，跨页继续读取，尽量在句末切块，保留短尾句。
- `manager_sections` 描述每期实际提供的4.4节：`complete`、`partial` 或 `not_found`。
  `complete` 只表示识别到章节边界、相关片段全部提供，不等于已读完或完美解析整个PDF。
- 超过六段的长章节保留前三段和后三段，并标为不完整，避免无限扩大模型上下文。
  压缩器重新核对覆盖情况；普通召回摘录要么整段保留，要么舍弃，不会悄悄裁掉句尾的条件/否定词。
- 模型需区分事实、经理历史表述、可能解释与证据缺口。两期期末比例和金额不能分解买卖、申赎、
  估值的贡献；“不能证明主动加仓”也不能倒过来说成“已经证明是被动变化”。金额下降不能否定
  期间有过买入，不能在同一回答中先贴交易标签再用“不等于证明”撤回。
- 对比时必须检查旧期回顾和展望是否已提同一主题。措辞或强调程度变化不等于首次提出，
  展望不等于已兑现。章节有缺口时，只能说明已找到哪些表述，不能断言前期没有该观点。

这些季报问答改动共用原来的季报工具，网页和小程序的新问答都生效，不新增另一套分析模型。
2026-09-29 的组合研究另在 Web 新增问题/模式/刷新授权表单，小程序仍兼容默认综合请求。
已有原文无需重新下载，旧聊天记录不会被重写。修复后的真实复测记录见 [季报RAG评测](基金季报RAG评测.md)。

## 日期与资产表状态

例如一份2026年二季报在7月21日发布：`published_at` 是 **2026-07-21**，
`period_end` / `data_as_of` 是 **2026-06-30**。后者表示期末资产组合的时间，不是实时持仓，
也不是经理展望的发生日期。`data_as_of_basis=report_quarter_end` 明确说明按已核对季度计算季末，
不是声称从原文逐字识别出所有日期；未知季度返回空值，不用披露日补齐。

`allocation_tables` 保留两份报告中八类资产主项的状态与原文：

| status | 通俗含义 | 是否计算比例差值 |
| --- | --- | --- |
| `value` | 两列数字和总资产口径均能可靠识别，明确的0.00也算数字 | 两期都是此状态时才计算 |
| `reported_dash` | 原表这行的金额、比例两列均写横杠 | 不补成0，不宣称已经清仓 |
| `not_found` | 没找到该资产主项；也可能未识别到5.1表 | 不猜原文是横杠，不伪造页码 |
| `parse_failed` | 找到了主项，但数字损坏、列不全或表头口径无法可靠确认 | 保留原文供核对，不算差值 |

`allocation_changes` 原来的 `before` / `after` 数字结构不变，增加两侧状态；横杠那一侧仍为null。
两期都没有可靠数字的主项可在 `allocation_tables` 查看，不会为了展示差值而制造零值。
表头和主项原文按物理页直接加入工具证据，不依赖关键词排名；每行最多240字，异常长内容用
`quote_truncated` 标识。这里只覆盖八类主项，不声称提供完整表格或全部子项。

旧数据库已经保存的页文本会在读取时生成这些字段和数字视图，保证状态与数字来自同一遍解析；
不覆盖原文、数据库里旧的数字缓存或旧答案，不新增数据库迁移，也不重新建立产品向量索引。
压缩策略 `fund_report_sections_v3` 保留这些字段，资产表预算不会挤占经理章节的4200字预算。

仍使用“AI 对比分析”提问，例如：

- 015789两期季报：“固定收益投资原表怎么写？是否能判断已经清仓？”
- 110020两期季报：“基金投资比例变化多少个百分点？数据截至日和披露日分别是哪天？”

预期回答会区分原表横杠与缺失证据、区分6月末数据与7月公告。无需重同步，重新发送问题即可；
历史错误回答仍保留以便复核，不会被后台悄悄修改。

## 经理观点与原文逐条对齐

继续使用“AI 对比分析”，不新增页面、按钮或模型。比如问：

> 对比两期基金经理运作分析，商业航天的关注重点有哪些延续，哪些变化？请给出原文。

现在返回的正文先展示与问题相关的配置数字、带两侧原文短句的观点比较，再展示程序生成的
两期日期与阅读范围。网页、小程序、SSE输出和历史回看使用同一份正文。

### 模型与程序各做什么

- 模型从 `allocation_changes` 选择相关项目；金额、比例、差值、横杠状态由后端展示，不手写另一套表格。
- 观点使用 `topic / relation / interpretation / basis / inference_limit / before / after`。每侧最多两个引用，引用只包含
  `sentence_id` 与 `source_kind`。模型不再抄写原文；后端回填原句、基金、文档、季度、页码与链接。
  `source_kind` 区分披露回顾、未来展望、两者混合、时态待确认，标签是模型判断，不是程序认证。
- 后端只接受压缩之后实际提供给模型的片段；原始工具日志里存在、但已被删掉的段落不能作为引用。
  错误恢复进一步压缩时，最终核对重新读取实际工具消息。
- 新版原句按句末切分，保留换行、分号列举、否定及长句条件。正文不重复放两份；编号绑定文档、
  页码、片段内容和位置。选了编号就回填完整原句，不接受模型另交 `quote`。跨页边缘可能是句子摘录，
  编号不保证独立语义完整；需联系前后文，必要时选择相邻句。数字表格的现有核对逻辑保持不变。
- “主题延续”“强调变化”要求两期经理章节证据；“某期未提及”要求该侧章节完整，并显示为
  **模型在该章节未识别到对应主题**。程序不声称验证了概念缺席，更不证明全文未披露或主题已放弃。

### 范围与编号

阅读范围明确写为“已提供的经理第4.4节、资产表主项和相关摘录”。章节是否完整由
`manager_section_coverage` 计算，模型不能自己填写“已读完全文”。没有完整章节时，仍可比较
已有双方表述，但不能作“缺失侧未提及”的判断。

`manager0` 等是机器片段编号，不是原文“第一条”。模型解释中不写“第几条/项/页”，
直接说主题；原文引用内的真实“二是……”可以保留。校验器对常见全文覆盖/编号/链接表述
作格式检查，遇到这些文字要求模型重写为主题解释。这种有限格式检查不等于理解了全部自然语言。

### 失败与保存

引用不存在、基金/季度不一致、原文不匹配等问题，最多在同一个模型上无工具修正一次。
达到工具轮数上限的强制总结也走相同校验。修正失败/超时不展示错误草稿；取消正常传播。
这次格式修正复用现有模型工厂，`thinking=False`，整体上限20秒，覆盖配置中的供应商切换；
主分析仍保持原有模型和思考/时限设置。不会为了通过评测延长每题120秒的执行上限。

`AgentChatResponse.report_answer_check` 和历史消息同名元数据保存：章节范围、实际引文、
配置项目、核对状态、修正次数及诊断。状态 `consistent / corrected` 仅表示引用协议通过，
`limited` 表示未能完成核对；**都不是投资观点正确性评分**。旧消息没有该字段时保持原样。

引用定位正确仍可能搭配错误的解释、过度推断或遗漏主题。语义需对照原文复核，不能靠这层
检查声称回答“100%正确”。评测记录保留引用核对材料，不更改旧考卷或自动分数来掩盖语义问题。

### 原句编号版（2026-09-15）

新版记录为 `fund-report-answer-v2`，旧版 `v1` 历史仍能回看，不需要数据库迁移、重新同步PDF
或重建向量索引。主Agent、模型轮次、工具权限、数字计算和共享时间预算都不变。

模型可见的工具消息内，`evidence[].text` 换成按原顺序排列的 `sentences`：

```json
{"sentence_id": "rs_0123456789abcdef0123", "quote": "这里是服务器从当前片段保留的原句。"}
```

上面编号仅为格式示例。回答只选择真实消息内的编号，不能自行拼接原文或使用其他季度编号。
错误恢复再次压缩时会无损恢复文本、执行原有片段预算、重新给保留片段编号；已删除片段不会回来。
原始工具输出仍保存原来的结构，只有实际送给模型的视图变化。最终正文显示“模型解读”及引用语境，
不是一串机器编号。

提示词要求广泛主题比较先核对主要列举项，不用无关定投/止盈话题替代IPO等关注点；同时区分经济
数据变化、利率变化和操作变化。它改善分析约束，但不能保证模型不会遗漏或混淆，仍需真实评测。
评分器现将 `limited`、无核对记录或仅有链接而未作答视为未完成，并保留专项文字筛查及人工验收项。
新评分版本与旧成绩分组，不倒改历史结果，详见 [季报RAG评测](基金季报RAG评测.md)。

### 引用语境与推断分层版（2026-09-15）

在上述原句编号基础上，新记录升级为 `fund-report-answer-v3`。原句编号算法不变；旧v1/v2记录
仍能读取，旧答案不会自动重写。无需重新同步季报、迁移数据库或重新编译小程序。

- `basis=disclosure_comparison`：显示“披露对照（模型概括）”，只概括、对照季报表述。
- `basis=inference`：显示“模型推断（非季报结论）”，必须填写 `inference_limit`，说明缺少的依据、
  前提或其他解释。不确定和未提及判断必须放在这一类；同条混合对照与推断也按推断展示。
- 分类由模型给出，后端只检查格式及分类/字段的一致性。即使写了“披露对照”，也不等于程序
  证明该句话是事实；推断的限制文字也可能需要人审。

每个模型选句由服务器附上本轮可见的前、后各一个句子单元，保存在 `context_before/context_after`。
它们单独标成“相邻语境”，不冒用模型给选句打的回顾/展望标签；各自保留原始文档、物理页和链接。
每个主题的同一季度内，相邻句与已选原句去重，不递归扩展，也不按字符数截断否定词或限定条件。

例如模型只选了“重点关注需求端的突破”，后端仍会把紧接着的“手机直连卫星、车载卫星通信……
有望……”展示出来。提示词同时要求模型优先选含具体细节的句子，不能只引用主题标题。
这些措施改善了可核对性，不保证任何一个相邻句都相关，也不保证一跳窗口就是完整语境。

跨片段衔接只用于经理章节：切块前记录全节连续编号 `section_chunk_index`，只有编号连续、基金和
版本相同、物理页相同或相邻的两个可见片段才连接。中间片段被压缩删掉就停止衔接；旧资料没有
顺序元数据时只取片段内语境。选句和相邻语境都以最终实际ToolMessage为准，不读取原始日志补证。

主Agent、数字算法、检索范围和时间预算不变；仍只有原总结轮及至多一次无工具修正，没有新裁判
模型。网页、小程序、SSE和历史保存共用后端生成的同一份Markdown正文。

## 按需资料与简洁回答

入口不变，不需要重新同步季报或编译小程序。用同一对报告重新发送问题即可：

| 问法 | 路径与结果 |
| --- | --- |
| 基金投资增加多少个百分点？ | 轻量数字题：相关表格主项、表头、两期日期与原文链接；同一模型关闭深度思考 |
| 继续沿用刚才两期，基金投资到底增加了多少个百分点？ | 重新判断当前问题，沿用会话冻结的版本，仍是轻量数字题 |
| 权益投资增加多少？是否说明主动加仓？ | 混合题：完整上下文，保留归因限制和原文，不把解释问题降成查数字 |
| 两期经理关注方向有哪些变化？ | 经理文字题：保留经理章节和相关召回，不携带未请求的专门资产表，思考模式不变 |
| 详细展开经理观点和限制 | 经理文字题，并展开相关说明；普通回答不重复罗列所有内部口径 |

### 怎样选择

`report_query_profile` 识别八类标准资产主项、有限数字问法和明确的经理文字问题，不另加分类模型。
存在未识别内容、简称、含糊指代或解释要求时保留完整路径。因此不是所有看起来简单的句子
都会进入轻量路径；宁可多读，也不依靠一个“多少”关键词漏掉后面的风险或买卖问题。
选择每轮重新计算，不把上一轮的轻量模式记成下一轮的默认模式。

本次不改变原始hybrid/keyword检索、不跳过embedding、不改Python数字计算、主分析时限或工具权限。
轻量化发生在实际ToolMessage进入模型之前：数字题只保留所问资产行和表头；经理文字题
省略专门资产表、保留经理段落和普通召回；混合问题保留完整路径。所有路径去掉文档元数据里重复的facts副本。
原始工具结果保留在当次返回的AgentToolCall中，筛选后的实际证据才进入引用核对，不能从原始结果补回未读内容。
会话表仍只保存工具摘要和核对记录，不新增全量原始工具日志表；完整报告页文本继续保存在文档库。

最新优化还会优先展示经理原文，对普通摘录只做同基金、同版本、同页的完整包含去重。
校验器仍拒绝把普通检索编号当成经理章节；修正时给出具体错误上限及同页经理句候选，
不自动替换引用。逐轮诊断和真实前后对照见 [稳定性优化复盘](季报问答稳定性优化复盘.md)。

### 阅读范围与输出

- 轻量题显示“经理章节本题未读取”，内部状态为 `not_requested`，不是 `not_found`。
  模型只能选择本题全部指定资产，不得插入经理观点、遗漏项目或增添无关资产。
- 两期都没有数字的主项也显示横杠/缺行/解析失败等状态，不补零；已有数字与差值不重新计算。
- 正文先给出已核对的数字/观点与引用，再列日期与阅读范围；常规回答只显示本题适用的限制。
  要求详细时展开，并将内部英文字段名转为中文。
  历史消息的核对记录仍保存完整限制，不因正文精简而丢失审计材料。
- `report_answer_check.query_profile` 保存路径、资产项目、详细模式，以及筛选前/实际压缩后证据字数。
  这里是字符数，不是Token；Token仍以供应商返回用量为准。

轻量路径仍经过现有工具调用、Hooks、版本校验、强制总结与最多一次引用修正。
复杂主题题的深度思考配置未改，不能承诺所有问题都变快。测试和真实耗时对照见
[季报RAG评测记录](基金季报RAG评测.md)。

## 分段耗时与共享预算（2026-09-15）

这轮接在按需资料之后，解决复杂问答难以定位慢点、重试可能超过整体等待时间的问题。
入口不变，不增加前端页面、不重新同步季报，也不改变其它Agent业务。

### 时间怎样计算

`fund_report_runtime.py` 给每次季报问答创建独立时间账本，记录准备上下文、模型选择工具、
读取证据、整理分析、引用核对、单次纠错。一次模型尝试的耗时包含供应商链，重试分别记录。
这里记录耗时、状态和次数，不记录模型思考或未经核对的草稿。

- `FUND_REPORT_TIMEOUT_SECONDS=110`：从核心Agent入口开始，路由准备、读取、分析及纠错共享预算。
  产品层此前的会话/版本读取、此后的保存不在此时钟内，不声称整个HTTP请求严格110秒结束。
- 主分析给原有一次纠错预留20秒；阶段还受原 `AGENT_MODEL_TIMEOUT_SECONDS` 限制。
  SDK重试关闭，现有Recovery最多两次尝试，但只有剩余时间允许才会重试。
- 退避等待、模型供应商切换都消耗同一预算；剩余不足3秒不再发起恢复调用。
  纠错最多20秒且不能超过总剩余时间。没有错误时立即返回，不会等满预算。
- 季报JSON草稿不再进行字符串式续写，格式不完整进入既有一次修正；普通聊天续写不变。
- 超时提示具体阶段；取消正常传播。已保存季报不会删除，也不会为了补救超时自动重新采集。
  引用修正失败只返回明确的有限结果，不发布错误草稿。

注意：异步取消能停止等待模型响应，但不能强制杀死Python线程里已经发出的同步读取。
季报检索沿用只读工具、embedding单次15秒且不自动重试；迟到的结果不会进入已失败回答。
总预算不是自动终止远端已收到请求的保证，超时的供应商Token也不能按0计费。

### 整理模式

`FUND_REPORT_SYNTHESIS_MODE` 支持以下三种模式，**当前默认仍是 `standard`**：

- `standard`：完整题沿用模型默认思考设置；明确数字题仍采用前一轮的轻量路径。
- `evidence`：只在证据已读取成功、问题明确比较历史经理主题/策略/久期时关闭整理轮思考。
  原始工具选择轮不变。因果、买卖、预测、风险适配和未识别问法仍保留默认模式。
- `balanced`：相同任务边界，但整理轮保留思考并指定 `reasoning_effort=low`。
  evidence在实测中出现引用和解释问题；balanced也仍有超时/主题遗漏，均只保留为实验开关。
- 这不是另开一个Agent，也不是删掉经理章节；两种模式的工具结果、压缩、引用协议完全相同。
  模型参数复用现有工厂，参见 [DeepSeek思考模式文档](https://api-docs.deepseek.com/guides/thinking_mode/)。

同题实验使用服务端 `report_synthesis_scope`，通过ContextVar隔离，不修改并发用户请求的设置。
可使用 `scripts/eval_fund_report_mode.py` 重现对照；会产生真实模型用量，成绩与人审仍写入原评测库。
具体实测及默认模式决定见[季报评测记录](基金季报RAG评测.md)。

### 去哪里看记录

- 成功或有限回答：`run.report_answer_check.execution`，以及历史消息同名核对记录中的 `execution`。
- 运行观测：原 `AgentRunObservation.metrics.report_execution`，无新增数据库表。
- 失败的幂等请求：原 `agent_chat_executions.response_payload.report_execution`。
- 评测失败：场景 `execution_diagnostics`。没有完成答案时不伪造质量分或完整Token数。
- 服务日志：`fund_report_stage`，只包含run编号与分段数字，不输出密钥、原始报错正文或草稿。

运行失败会额外保留异常类别和HTTP状态码；402显示模型账户余额不足，401提示检查服务端配置。
充值可恢复余额错误，但不能保证复杂分析不再超时。真实验证中充值后仍复现了分析阶段超时。
