# 单基金回答事实核对

## 这轮解决什么

过去的证据索引只能说明“调用过这些来源”，不能证明答案里的数值正确。
现在单基金综合研究把关键事实与模型观点分开。后端只核对事实字段与本轮工具返回值是否一致，不宣称整段金融推理已经验证。

本次 v2 在原有核对之上补充“判断依据”：模型给出当前判断，并分别解释哪些事实支持它、哪些事实削弱它、适用条件是什么，以及哪些可观察变化出现后需要重新评估。没有反向证据就说明本轮缺口，不强行凑数。

## 数据流

1. `FinancialResearchBriefService.build_fund()` 完成原有研究和有限补查。
2. `build_answer_facts()` 从成功结果登记最多 19 条核心事实：历史风险、基金档案、部分披露持仓和市场规则观察。无值不补零，历史指标无统计期就不登记；每条披露用自己的报告日。
3. 事实连同 `fact:fund:...` 编号进入真实工具返回值。这个编号是本项目的字段引用，不是外部权威认证。
4. 原来的模型总结轮直接输出 `facts / judgments / uncertainties`，不是再加一个分析 Agent。若继续读取同一基金，每轮按工具调用顺序以最新成功结果重建校验上下文；失败结果不覆盖成功结果，不把新数值修正回旧值。若成功结果涉及多只基金，则不套用单基金核对协议。
5. `FundAnswerCheck` 检查结构、事实引用是否存在或重复、基金代码、数值、单位、时间范围，以及正反依据引用是否属于当前基金。草稿最多选 8 条事实；最终报告还补入判断引用但未入选的事实，保证这些依据也能逐条展开，因此最终事实展示数可以超过 8 条。正反证据保留各自统计范围，不把不同日期或长短期差异直接判为矛盾。
6. 核对发现问题时，把具体错误、最多 24000 字符的原草稿和真实清单交回未绑定工具的模型，只修正一次（`max_attempts=1`、`allow_continuation=False`），禁止自动续写及额外重试。它不执行工具或刷新数据；正常结束和达到工具轮数上限后的最终回答都经过核对。
7. 修正仍有问题、调用异常或异常返回工具调用时，撤下整个草稿，避免留下基于错数字的观点。仅展示已有工具事实（最多 8 条）与明确缺口；没有可核对事实时同样降级，不展示模型判断。
8. 核对结果写入 `AgentChatResponse.answer_check` 和助手消息 `run_metadata.answer_check`。完整助手及研究终端侧栏复用同一渲染器。SSE、复制文本和历史对话均使用最终结果；正文保留精简来源、口径、字段和判断引用，不向用户流出待核对的 JSON 草稿。

## 能查和不能查

- 能查：把 8.50 写成 85；把 % 改成元；引用另一只基金；把历史统计期写成未来一年；编造一个不存在的引用；结构损坏。
- 允许等价数字格式，例如 8.5 与 8.50；不允许偷换正负号或把 0.085 当成 8.50%。
- 核对范围限于结构、`facts` 字段、证据和用户背景引用。结论、正反关系解释、条件解释、重看事项和 `uncertainties` 中的自由文本不做逐项事实核验或语义证明。引用存在，只代表引用可追溯，不保证它支持该判断或推导正确；本轮也没有证明行情来源真实、实时或完整。
- 买卖、仓位及条件式投资观点不会仅因主题被拒绝，仍需遵守原有研究闸门与用户背景。
- 后端的缺口、披露警告和补查失败提示独立保留，模型不能将它们覆盖为“信息齐全”。
- 仅用于 `fund_research_brief` 窄路由。普通聊天、单独指标查询、组合研究仍按原协议运行；旧历史消息不回溯重算。

## 新判断的结构

| 字段 | 谁负责 | 通俗含义 |
| --- | --- | --- |
| `text` | 模型 | 当前判断或条件式观点 |
| `supporting_evidence` | 模型选引用并解释，Python 核对引用 | 哪些事实支持这句话，为什么 |
| `counter_evidence` | 模型选引用并解释，Python 核对引用 | 哪些事实削弱或限制这句话，为什么 |
| `supporting_evidence_gap / counter_evidence_gap` | 模型 | 对应证据为空时，明确本轮缺少什么，不能把“没查到”当成“不存在” |
| `conditions` | 模型解释，Python 核对背景字段来源 | 当前观点在哪些条件下适用 |
| `change_triggers` | 模型 | 哪些可观察变化发生后需要重看，不代表自动监控任务 |
| `evidence_ids` | Python 合并正反引用 | 保持原有引用消费者兼容，模型不用重复填写 |
| `investment_background`（报告级字段） | Python 复制本轮已确认背景 | 保存判断实际引用的用户原话与出处，供界面及历史回看展示 |

每条判断正反依据各最多 4 条，条件和重看事项各 1 至 3 条。正常路径仍然只使用原有总结轮；说明更完整会增加一些输出 token，但不会因此新增审核 Agent、模型往返或数据刷新。

### 条件来源不能混淆

- `user_context`：用户已经提供的条件，必须引用本轮已确认的 `horizon / loss_tolerance / liquidity / purpose` 字段。用户原话由后端自动加入，模型不能编造一个 `quote` 字段。
- `assumption`：模型提出的适用前提，界面标为“模型假设”，`background_fields` 必须为空，不能冒充用户背景。
- `missing_information`：还需要用户补充的条件。指定字段时不得把已经确认的字段说成缺失；其他细节问题可以不指定字段。

背景通过现有 `current_investment_context()` 读取，不新建 Memory 或数据库表。待确认状态不当作有效背景；只保存本条回答实际引用的用户背景快照。用户后来改变条件，不会改写历史回答的原话。

主要代码入口：`app/services/fund_answer.py` 的 `instruction()` 定义模型输出约定，`check()` 做结构与引用检查，`finish()` 构造最终报告，`render_answer_text()` 生成复制和流式使用的正文。数据结构在 `app/schemas.py`，共享界面在 `app/static/fund-answer.js`。

## 现有界面复用

本功能按 Operate 模式扩展现有回答区域：沿用石墨灰底色、黄色强调及既有状态色、字体、断点与终端栏布局，不引入新设计系统或重新设计页面。每条事实使用原生 `details / summary` 渐进披露，收起时保留名称与数值，展开后显示对象、统计范围、口径、来源、工具字段和引用编号。

完整助手和终端通过 `fund-answer.js` 渲染同一份报告。新回答使用 `fund-answer-v2`：先显示结论，点击“判断依据与适用条件”展开正反说明、相应事实和时间范围、用户原话、模型假设及重看事项。原有 `fund-answer-v1` 报告仍按旧样式显示，不补造旧报告没有的解释；无匹配版本的历史消息回退到原有 Markdown。

来源链接只接受绝对 HTTP(S) 地址，外部文本转义。复制及后续历史上下文使用后端最终正文，其中保留来源、口径、字段、正反解释、条件来源和重看事项，不依赖折叠区元数据才能追溯。

## 页面测试

在 AI 助手选中基金并发送：

> 请全面分析当前基金，给出当前判断、支持依据、反向依据、适用条件，以及什么变化出现后需要重新评估。没有找到的证据请说明缺口，不要凑数。

结果应分成“工具事实 / 模型判断 / 不确定性与待补充”。展开某条事实，可见基金、统计期、口径、来源与工具字段；展开判断可见正反依据、适用条件和重看事项。刷新会话后仍可展开。无需开启公开补查，默认读取已保存数据；公开刷新仍须手动开启，默认值保持 `false`，展开依据或列出重看事项都不会触发刷新。

还可以在同一会话先说“这笔钱三年不用，最多能接受亏损 15%”，再发送上面的问题。若判断用到这些条件，展开后应显示“用户已提供”和实际原话；其他前提应标成“模型假设”或“待你补充”。这不是根据你的这句话直接评定投资者风险等级。

实际状态可能是“关键事实与工具一致”“关键事实已修正”或“事实核对未完成”。不应为了演示修正而故意改写真实数据库；自动测试使用假模型制造错数值、错统计期和超时。
