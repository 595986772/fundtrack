# 盘中市场行情

## 使用

进入「板块雷达 -> 市场环境」。最上方是全市场A股成交额，中间是七指数盘中成交，
下方仍是原来的日线研究。两个更新按钮分别控制全市场与指数，不互相触发。

打开页面只读数据库，不联网抓取；点击「更新盘中行情」后请求腾讯公开行情，一次获取七个指数。
30秒内重复请求共享结果，没有定时轮询，也不会触发新闻采集或大模型。

## 日成交额走势（当前界面）

市场环境的曲线已经改为**分日**：一个交易日一个点，可切换「近30日」「近3个月」。
两个周期分别表示30/90个自然日范围，只画来源返回的交易日，不补周末和节假日的零值。
为避免把盘中累计额当全天金额，当前只纳入今天之前的日线；图中显示真实截至日期。

- 支持七个指数（含科创50）和「沪深成交额参考合计」。不再显示分时日期选择器和手动采样曲线。
- 沪深参考合计是上证指数、深证成指的同日成交额之和，**不是**页面上方逐股汇总的沪深A股金额，也不包含北交所。图下单独显示这个口径限制。
- 两项数据日期不齐时，该日合计为空、曲线断开，不能补零或相加不同日期金额。
- 「更新日成交额」仅更新当前所选序列的历史；3分钟内共享结果。导航、切换市场、切换周期均只读缓存。
- 盘中行情刷新与日线刷新独立，盘中值不进入日线曲线。旧分时历史兼容保留，但不作为当前曲线的数据来源。
- 日线缓存使用`market_intraday_cache`中`daily:<series_id>`的独立记录，无新增数据库迁移。

### 日线字段核对

使用腾讯公开日线接口`newfqkline/get`，只请求白名单指数，最多两次12秒超时请求。
腾讯日线数组第5列为成交量（手），第8列为成交额（万元），后端把金额乘10000统一为元。
特别注意：AKShare的`stock_zh_index_daily_tx`把第5列命名为`amount`，但[其文档](https://akshare.akfamily.xyz/data/index/index.html)明确标的是手数，不能直接当成交额。

2026-09-09核对科创50的2026-09-08日线：腾讯第8列`7871391.45`万元，即`787.139145`亿元；
[中证官网](https://www.csindex.com.cn/zh-CN/indices/index-detail/000688)同日`tradingValue`为`787.14`亿元，符合其显示精度。
东方财富历史接口当次未连通，未把错误响应或已有分时快照作为日线替代。
首次补齐后，八种口径近90日范围各有63个交易日记录；这是当次连通记录，不是固定条数。

模块：`market_daily_turnover.py`负责日线校验、合计、缓存和节流；
`market-turnover-chart.js`使用ECharts分类轴按交易日期绘图，不平滑、不跨空值连接。

接口：

- `GET /api/v1/market/turnover/daily?series_id=index:sh000688&period=30d`
- `POST /api/v1/market/turnover/daily/refresh?series_id=index:sh000688&period=3m`

## 旧版分时采样（兼容保留）

以下是上一版本的存储和API说明，当前日成交额界面不再使用这套采样曲线。

「全市场成交额」下方新增「成交额变化」，可选择沪深两市、沪深北、单个交易所，
或包括科创50在内的七个指数，共12种独立口径。日期可选最新记录或已保存的历史日期。

- 横轴为北京时间的来源行情时间，纵轴为当日累计成交额（亿元），不是资金净流入。
- 这是**手动采样曲线**，不是连续分时行情或每日收盘成交额的30日/3个月走势图。
- 更新全市场成交额时记录五种市场口径；更新盘中行情时记录七个指数。刷新成功后曲线自动重读本地数据，不追加外部请求。
- 初次接入只有之前最后一份快照。只有1个真实点时显示散点和提示，后续不同来源时间的采样点才连接为虚线，不补开盘零值、不补缺失时段。
- 不同日期分开展示；午休和未采样期间保留真实时间间隔，不生成中间观测。
- 同一序列、同一来源时间只保存一个点。来源修正可更新该点；失败、节流和时间回退不会创建假点。
- 金额回落不强制拉平，而是提示来源修正/覆盖变化；证券覆盖数量变化也会提示，不把点间差额解释成资金净流出。
- 展开采样明细可核对来源时间、累计金额、抓取时间。切换市场、日期和曲线重读按钮均只查数据库。
- 保留近90个自然日的采样，数据重启后不丢失。早于接入时间、没有存下来的盘中路径不能恢复。

实现分层：两个行情服务把已验收的旧/新点与最新快照放在同一个数据库事务中提交；
`market_turnover_history.py`负责去重、保留期和按日期读取；
`market-turnover-chart.js`使用项目现有的本地ECharts库绘制。独立图表读取失败不使行情采集被误报为失败。

## 全市场成交额

点击「更新全市场成交额」后，独立读取[新浪沪深北A股列表](https://vip.stock.finance.sina.com.cn/mkt/#hs_a)：

- 分别统计沪市A股（含科创板）、深市A股（含创业板）、北交所A股。
- 沪深两市A股 = 沪市A股 + 深市A股；沪深北A股 = 三个互斥证券集合之和。
- 不含B股、基金、债券，不把各指数金额相加；科创板/创业板已包含，不再额外相加。
- 3分钟内共享一次刷新结果。只手动采集，无自动轮询/重试或绕过限制。
- 先取来源证券数量，按代码排序以每页100条读取，再核验数量与去重后的覆盖。
- 45秒采集预算、最多8000条；任何缺页、冲突重复、未知代码、缺失金额都不发布新合计。
- 来源明确给出的零成交可以保留；空值不当零；失败保留上一完整批次及其时间。

字段依据是 [AKShare 的新浪A股文档](https://akshare.akfamily.xyz/data/stock/stock.html)
与本地已安装适配器：`Market_Center.getHQNodeData` 的 `amount` 单位为元。
本实现保留原始数值校验，不沿用第三方把缺失值转成NaN后直接求和的行为。

**时间限制：**该列表只返回逐股时分秒，没有逐股独立交易日期。
本实现用采集首尾的同源上证行情核对参考日期，同时显示实际采集窗口；
不声称已逐股核验日期，也不声称是同一毫秒截面或交易所最终结算金额。
覆盖数量以新浪A股列表为准，不等于用交易所证券名册独立审计过的数据完整性。

2026-09-09的实际连通测试覆盖5559只来源记录，约5秒完成；这只是当次记录，不是固定股票数量。

## 数据口径

- 上证、深证成指、沪深300、中证500、中证1000、创业板指、科创50，均按来源返回的指数口径。
- 范围可能重叠，不把各行相加为全A股成交额，不宣称深证成指仅统计成分股成交。
- 科创50代码为000688，不等于整个科创板。按[上交所公告](https://www.sse.com.cn/market/sseindex/diclosure/c/c_20250418_10777363.shtml)，自2025-04-21起其成交金额（量）口径为指数样本的成交金额（量）。
- 盘中是截至行情时间的累计值，不是最近一分钟增量，不与日线5日均值直接比较。
- 没有逐笔实时保证。旧日期显示「非今日行情」，同日明显落后显示「行情时间偏旧」。
- 午休/收盘不要求行情继续跳动；这是时效检查，不依赖周几去宣布今天必定开市。
- 网络或单行异常保留对应的旧数据及旧时间；失败不能把数据变为零或“今日最新”。

这是网页公开行情源，不是有稳定性承诺的商业行情API；来源格式变更时应重新核验。

## 模块与边界

- `app/services/market_intraday.py`：Provider、校验、时效判断、缓存与刷新节流。
- `app/services/market_turnover.py`：全市场列表Provider、互斥分组求和、完整批次缓存。
- `app/models.py` 的 `MarketIntradayCacheModel`：最近一次有效行情，重启后保留。
- `MarketTurnoverPointModel`：成交额真实采样历史，与最新缓存和日线数据分开。
- `GET /api/v1/market/intraday`：只读；`POST /api/v1/market/intraday/refresh`：鉴权后手动刷新。
- `GET /api/v1/market/turnover`：只读；`POST /api/v1/market/turnover/refresh`：手动更新全市场成交额。
- `GET /api/v1/market/turnover/history?series_id=index:sh000688&data_date=2026-09-09`：只读科创50指定日期的采样。省略日期则读最新有记录的日期。
- `app/static/market-intraday.js`：独立状态和表格；与日线模块分别成功/失败。
- `app/services/market_indices.py`：统一的七指数配置，日线另用AKShare新浪源保存最近90个交易日，计算近30个交易日和近3个月（60个交易日）的涨跌、波动与回撤。科创50也进入日线Agent工具；不以盘中累计值冒充日线指标。
- 不写入 `market_snapshots` / `market_index_bars`，不进入旧版日线Agent证据计算。

本地自动建表沿用项目配置；关闭自动建表的部署先执行 `alembic upgrade head`。
最初的迁移仅新增 `market_intraday_cache` 表；全市场复用其独立记录`all_a_turnover`，不需要新表。
曲线另新增`b57d8e20af16`迁移，创建`market_turnover_points`。旧快照会作为起点只读展示，
在下一次手动采集时随新数据一并保存，GET本身不做隐式数据迁移。
