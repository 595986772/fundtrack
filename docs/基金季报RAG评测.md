# 基金季报 RAG 质量评测

更新：2026-09-14。套件：`fund_report_rag_v1`。

## 先理解这轮在做什么

之前验证的是“能下载、能检索、能回答”。这轮增加一份固定考卷，重复检查同一批问题，
把检索漏掉、表格数字错误、版本串用，以及需要人判断的解释问题记录下来。

**评测不会自动修改 Prompt、检索参数或模型，也不会越跑越聪明。**
它提供改动前后的可比依据；调优仍然由你明确修改代码后重新运行。

## 页面用法

1. 打开 [开发者工作台](http://127.0.0.1:8000/developer#research/chat)。
2. 点击右上角“运行详情”，切到“评测”。
3. 评测套件选择“季报 RAG · 三类基金”。默认 `hybrid` 使用真实语义加关键词检索。
4. 首次建议点击“冒烟 3 条”，确认费用提示后运行。后台先核对固定 PDF、建立独立索引，
   再逐题运行 Agent。索引已有且完整时会复用。
5. 可以关闭页面。下次选择同一套件，点击“继续查看”，不会重建已受理的任务。
   “取消任务”是协作式取消；已发出的模型请求和费用无法撤销。
6. 在“评测记录”切换历史运行，展开题目，查看检查项、参考答案、物理页链接、完整回答、
   检索原文和逐轮引用。复核结论可设为“待人工复核 / 人工确认 / 需修改”。
7. “需修改”必须填写具体原因。保存只更新复核记录，不改模型原始回答和自动分数。

保存期间会锁定套件、检索配置与记录选择；读取历史记录失败时保留并明确标识上一份结果，
提供就地重试。同页未提交的复核草稿按用户、运行和题号分别保留，保存别的题不会清空它们；
这些未提交草稿仅在当前页面内存中，刷新浏览器前仍需保存。

`keyword` 是关键词对照组，不调用 embedding，但回答仍调用真实大模型。打开页面、
切换套件/检索配置、查看原文和保存复核均不调用模型。完整集有 20 个场景，包含追问场景，
所以实际模型轮数大于 20；同一次任务内部顺序执行，不并发轰炸服务商。

此入口沿用现有管理员权限。小程序和普通产品页面没有新增测试按钮。

## 固定考卷

| 类型 | 基金代码 | 样本 |
| --- | --- | --- |
| 指数联接 | 110020 | 2026-Q1、2026-Q2 |
| 主动权益 | 015789 | 2026-Q1、2026-Q2 |
| 债券 | 110007 | 2026-Q1、2026-Q2 |

- 六份公开 PDF 保存在 `data/evals/fund_reports_v1/pdfs/`。
- `documents.json` 保存来源 URL、披露日、文档 ID、SHA-256 和逐页文本。
- `data/evals/fund_report_rag_v1.json` 保存 20 个场景的独立数值标注、参考答案、原文短句、物理页码和复核标准。
- 参考答案由编码助手对照原文整理，**仍待项目所有者验收，不是已经获得专家认证的标准答案**。
- 每次运行重新解析原 PDF，但不重新下载“最新报告”。文件哈希和原文页文本必须匹配。
- `scripts/freeze_fund_report_fixtures.py` 仅用于显式制作样本，现有考卷存在时拒绝覆盖。

当前覆盖数值与百分点、跨页表格、横杠缺失值、经理观点、历史与实时边界、联接基金范围、
多轮版本沿用。它不是覆盖所有基金与报告版式的行业测试集。

## 分数到底表示什么

| 指标 | 自动核对范围 | 不代表什么 |
| --- | --- | --- |
| 标注证据召回 | 实际工具结果的原文/表格事实是否包含标注短句和物理页 | 不等于模型最终看到了完整关键段落，更不等于答案正确 |
| 披露数字核对 | 工具计算的两期比例、百分点变化和总资产口径是否匹配独立标注 | 不自动检查模型自由文本中的每一个数字或因果结论 |
| 引用可定位 | 回答 URL 是否属于指定的两份 PDF、物理页码是否在范围内 | 不等于该页支持引用旁边的观点，也不检查外部站点当时是否可访问 |
| 版本隔离 | 每轮实际工具输出和跨轮会话引用是否保持同一基金、同一对文档 | 不等于整个会话解释正确 |
| 执行与效率 | 工具路由、失败、数量、真实检索模式、耗时和主 Agent Token | 不是收益预测能力或投资建议质量 |

比例保留分子/分母，例如 `6/6`。没有适用项时显示“不适用”，不是假定 100%。
执行失败单独显示，页面列出完成评分题数，失败题不进入召回等比例的分母。
多轮场景的版本检查覆盖所有轮次；召回、数字和引用比例评价末轮问题，完整逐轮回答保留供复核。

尤其要人审：引用是否真的支持观点、否定词、首次出现与持续关注的区别、未知是否被补零、
资产比例变化是否被说成交易原因，以及无法回答的问题是否明确承认缺口。

主 Agent Token 汇总包含追问，不包含 embedding Token。面板总耗时从索引准备完成后开始；
Job 的起止时间还包含索引准备。`hybrid` 请求实际降级为关键词时会明确判为检查未通过。

## 数据流和隔离

```text
管理员显式运行
  → FastAPI 校验套件、case_id、身份与幂等键
  → 持久化 fund_report_eval Job（默认不自动重试整套）
  → 校验 6 份固定 PDF
  → 临时 SQLite 装入当前解析结果
  → 独立评测 Chroma 索引
  → ComprehensiveAgentService / 原有 Agent Loop
  → 原有季报研究工具，读取评测上下文中的 Service
  → 自动检查 + 完整回答/原文 + 待人工复核
  → 现有评测、运行观测表
  → 开发者面板
```

`ContextVar` 仅切换本次评测的季报读取实例，可跨 `await` 和 `asyncio.to_thread` 传播；
其他用户请求继续读取产品数据库。每题使用新的评测会话，第二轮只发会话 ID 和问题，
由生产会话逻辑恢复基金与文档 ID，不在测试器里偷偷把答案上下文补回去。

临时 SQLite 在结束后清理；取消索引准备时先等线程退出再清理，避免线程继续访问被删除的数据库。
评测向量缓存保存在 `data/eval_indexes/`，不进入 Git，不覆盖产品知识库。
产品数据库只保存本轮评测、运行观测和 Job 记录，不修改你的真实组合、持仓或已有聊天。

同用户重复提交同一组场景、配置和幂等键会返回原 Job。页面将未完成的任务编号存在本机
localStorage；浏览器清理此存储后不能自动恢复入口，但仍可通过 Job / eval_run_id 查询。

同组变化只比较相同考卷指纹、检索/embedding 配置和题组。代码版本另存运行指纹，
因此可以修改检索实现后对同一考卷比较。切换模型等外部设置后，仍应人工核对运行配置是否可比。

## 本轮验证与已发现的问题

- 离线后端相关测试共 114 项通过；前端测试 177 项通过。假模型测试只验证程序行为，不计入真实模型成绩。
- 实际使用 DeepSeek 与 Qwen embedding 跑了 **5 个场景、6 轮用户问答**，分为 3 题冒烟和 2 题跨轮/观点测试。
- 两次运行的自动检查均通过；3 题报告 `eval_826042d78e3547ab`、2 题报告 `eval_3b074bd06a214675` 已保存。
- 本轮没有跑完整 20 题，也没有运行真实 keyword 对照组，不能把这 5 题的分数说成全套质量结论。
- 所有答案尚未获项目所有者确认。编码助手初审将两项标为“需修改”，其他保留“待复核”。

**问题一：解释超出了两期数据。** 主动基金占比/金额题的数字和引用都正确，但模型一面说不能确定
主动加仓，一面又断言这是“被动变化”。两期期末金额不能分解买卖、申赎与估值的贡献。

**问题二：检索到了页面，不等于关键段落完整到达模型。** 经理观点题的回答承认 Q1 展望被截断，
却仍把终端应用说成 Q2 的新框架。Q1 第7页已提终端需求和 IPO。标准短句召回检查能通过，
但不能替代完整语义复核。当前经理章节提取对“基金的投资策略”这一标题变体覆盖不足，
叠加工具上下文压缩，是下一轮需要分别验证的环节。

本轮保留了这两个问题，没有偷偷修改 Prompt 或检索流程后再宣称评测全优。
下文记录在保留这份基线之后进行的修复，不覆盖原始答案和需修改记录。

## 回答质量修复（2026-09-14）

这轮没有修改考卷、标准答案、评分算法、模型配置或 Agent Loop，也没有新增测试页面。

1. 修复经理章节标题中的“的”字与排版空白，跨页保留短尾句，按句末优先切分。
2. 每期仍限制4200字正文预算，完整经理段落优先，普通召回使用剩余额度；不再把每段统一裁成700字。
   章节超出六段时保留首尾并标为 `partial`，`manager_sections` 随压缩结果重新计算完整性。
3. 补充季报专用提示词：区分事实、历史表述、推测和缺口，不从期末比例推断主动/被动原因；
   先查前期回顾与展望，区分方向延续、强调变化和真正的明确调整，不把计划当成已兑现。
   归因边界是双向的：期末金额增加不能证明加仓，减少也不能否定期间加仓；不先贴因果标签再撤回。
   用户只问配置数字时不附带整节行业展望，避免无关解释扩大出错面。

新增 `tests/test_fund_report_quality.py`：先在旧实现上复现失败，再验证六份固定报告的经理章节
通过实际 `compact_messages` 后仍保留完整证据、长章节明确降级、页码不串用、句尾不被再次裁掉。
这类离线测试验证程序行为和规则装配，不代表模型必然遵守提示词。

离线验证：123项相关后端测试、177项前端测试通过。真实复测使用相同固定原文与原有题目，
不修改旧运行，不把自动分数当作语义准确率。

## 日期与资产表状态修复（2026-09-14）

在上面记录的基线之后，接入了两个有明确范围的改进，没有修改固定PDF、题目、标准答案、
自动评分规则、模型配置、Agent Loop或前端页面。

1. 报告元数据增加 `period_end`、`data_as_of`、`data_as_of_basis`。
   已核对季度对应的季末为资产表截至日，公告 `published_at` 单独保留。压缩后仍包含两类日期。
2. `allocation_tables` 区分 `value`、`reported_dash`、`not_found`、`parse_failed`。
   真正的0.00仍是数字；横杠、缺行和无法解析都不补零。旧数字接口不改结构，差值增加两侧状态。
3. 资产表主项原文按页直接加入证据，另有每期2400字摘录预算，不挤掉4200字经理正文预算。
   读取已有页文本生成新视图，不覆盖数据库历史原文/缓存，不要求产品重下载或重建向量索引。
   解析状态与数字来自同一遍解析，避免旧数字缓存和新状态互相矛盾。
