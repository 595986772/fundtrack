# 持仓到投研报告

更新：2026-09-18。已打通持仓研究路径，并收拢 Web 报告的阅读顺序。不重做 Agent，也不改变实际持仓。

## 怎么用

1. 网页打开“我的资产 → 持仓”；小程序打开“资产”，选择账本。
2. 点击“查看收益与风险”。这里展示现有数据计算的收益、回撤、波动和风险证据。
3. 留意实际覆盖日期与观察日数。选择一年不代表新建账本已经积累一年真实收益。
4. 点击“分析当前配置”并确认后，才提交原有 LangGraph 研究任务并调用模型。不会顺便刷新外部数据或交易。
5. 完成后查看配置报告，也可直接打开上次报告。历史报告保留生成时的快照，不自动变成最新配置。
6. 点击“继续追问”（小程序为“继续追问这份报告”），确认输入框问题后发送。后端将该报告的事实、数值和来源接入上下文。
7. 后续消息沿用同一会话；点击“开始新话题”解除引用。切换到其他组合或基金也会解除引用。

报告不存在、无权读取或快照校验失败时显示错误，不偷偷改用最新一份。数据不足显示缺口，不补零或伪造结果。

## 持仓诊断页

网页入口仍是“收益与风险 → 查看上次报告”，也可从“AI 投研 → 研究报告”进入。小程序点击“打开配置报告”，进入独立的 `portfolio-report` 页面；以前的 `analysis?kind=research` 链接会跳转过去。

Web 阅读顺序为：结论与关键数字 → 分类依据 → 分歧与后续关注 → 多角色过程（有此模式时）→ 报告明细。
本轮不改小程序；小程序仍沿用原先最多三条关注点与其余观点展开的布局。

- Web 合并后端的前三条与其余观点，先按风险、支撑、中性分组，各组内沿用原顺序，不重新评分、改写结论或硬补机会。所有观点标题均可直接看到。
- 点击一条观点，即可在原处展开解释、关联持仓及全部引用。空分类只显示一行说明，不再占用半幅空栏。
- 每条观点可展开原有解释、数值、证据编号、数据日期和来源。没有直接来源链接就不凭空拼接；小程序可复制已有链接。
- 持仓占比与风险贡献来自报告时的冻结数据。不会把今天的仓位套在旧结论上，也不会把风险占比说成亏损概率。
- 业绩口径和历史报告日期始终可见。模型失败的规则回退不会伪装成 AI 结论。
- 完整指标、历史报告、调整研究和技术详情降为展开内容，没有删除对应后端能力。
- 多角色报告的研究员独立观点、相互质询和阶段记录放在最终结论之后，默认折叠；降级状态和分歧缺口仍明确展示。
- 快捷追问只填问题草稿，保留准确报告编号，用户发送后才调用 Agent。比较结果独立展示，不覆盖作为追问依据的原报告。

打开旧报告即可看到新版排版，不需要再次付费生成；只有明确点击生成、比较或发送问题才可能调用模型。

## 代码分工

- `app/services/portfolio_review.py`：只读业务汇总，复用业绩、风险和研究历史服务。只返回首页需要的摘要。
- `app/routers/portfolios.py`：新增 `GET /{portfolio_id}/review` 和 `GET /{portfolio_id}/research-runs/{job_id}`。
- `app/services/portfolio_research_audit.py`：按用户和组合读取指定的已完成报告，核对冻结快照。
- `app/services/portfolio_report_context.py`：把报告引用转为模型可读的证据上下文，包含数值、日期、来源和局限。
- `app/services/comprehensive_agent.py`、`conversations.py`：每轮验证并载入报告，在助手消息元数据中保存 `research_reference`；可见聊天历史只保存真正的问答。
- `app/static/portfolio-review.js`：网页的独立汇总页面状态；原高级工具保留为次级入口。
- `miniprogram/src/pages/portfolio-review/`：小程序对应页面；与原研究报告页共用 JobTracker 的任务身份。
- `app/services/portfolio_diagnosis.py`：纯展示转换器，在读取报告时附加 `diagnosis`。不联网、不调用模型、不修改报告和快照存储。
- `app/static/portfolio-diagnosis.js` / `.css`：网页诊断展示组件；网络和 Job 生命周期仍由工作区管理。
- `miniprogram/src/pages/portfolio-report/`：独立管理报告选择、证据展开、历史比较和追问，不再借用通用分析页。
- `miniprogram/preview/`：浏览器开发预览支持同一份原生 WXML 模板及旧链接跳转，不进入微信原生包。

两端共用后端计算和报告。重试复用幂等编号或已受理 Job；导航和“重读”仅查询已保存数据。

## 请求约定

`AgentChatRequest.research_job_id`：具体编号表示引用该报告；不传表示延续同一对话的报告；空串表示明确解除。传入编号时前端同时传 `portfolio_id`，后端仍检查用户归属，不信任客户端提示词。

报告引用不是长期记忆，也不是新指令。它不会授予工具权限、打开外部采集或替用户调整基金持仓。
