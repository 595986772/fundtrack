# 真实持仓账本

## 页面与录入

- 我的资产 / 持仓：显示份额、持仓成本、当前市值、浮动盈亏、已实现盈亏及累计盈亏。
- 旧模拟组合：点击“补录实际持仓”，录入每只基金的份额、成本及买入日期，确认后转换为真实账本。
- 新组合：通过“新建真实持仓”录入。添加基金的选项来自已关注基金目录。
- 后续买卖：进入“记账与流水”，区分已成交补记与待确认申请，支持登记确认、撤单结果及赎回到账。
- 误录更正：原流水不删除，通过带原因的更正或冲正重算有效账本。详见 [基金交易状态与账务更正](基金交易状态与账务更正.md)。

持仓数量的单位是“份”，不是元。成本是当前剩余份额对应的成本，而非历次买入金额的简单累加。
未持有的基金可以从录入草稿中移除；留下的每一行都必须填完整，不会静默丢弃未填完的基金。

## 计算口径

- 当前市值 = 持有份额 × 最新已披露单位净值。
- 市值占比 = 该基金当前市值 / 全组合当前市值。无需手填比例，也不能用不同基金的份额数量直接相除。
- 平均成本 = 剩余持仓成本 / 剩余份额。
- 浮动盈亏 = 当前市值 - 剩余持仓成本。
- 已实现盈亏：按交易日期重放流水，卖出收入扣除手续费及释放的移动平均成本。
- 累计盈亏 = 当前浮动盈亏 + 已记录交易的已实现盈亏。
- 组合累计收益率 = 组合累计盈亏 / 已记录累计买入成本；这不是年化收益率或时间加权收益率。

金额以各基金自己的净值日期为准，不是盘中估值。点击“更新净值”后重新读取持仓估值，不自动轮询。
未录入的历史卖出和分红等收益不计入累计盈亏；清仓后，已记录的已实现盈亏仍保留在组合汇总中。

## 实现边界

前端 `app/static/app.js` 移除了持仓的权重编辑器。原 `#assets/configuration` 地址保留，改为补录实际持仓。
旧组合只预填基金代码，份额、成本、日期保持空白，不从权重猜测用户资产。
确认后复用 `PUT /api/v1/portfolios/{portfolio_id}`；新建使用 `POST /api/v1/portfolios`。

后端复用 `PortfolioService.update/create` 的实际持仓分支，在事务内保存份额及初始买入流水。
转换保留组合 ID；保存失败保留原配置。有交易流水的账本不能被整体覆盖，重复转换也不会重复记账。
风险及 Agent 继续读取 `weight_pct`，但真实持仓的该字段由最新市值计算，是分析结果而非人工配置输入。
旧版权重 API 保留兼容已有研究逻辑和历史数据。后续记账升级已追加交易申请、事件、更正记录及精确数值列，具体迁移和边界见上述文档。
